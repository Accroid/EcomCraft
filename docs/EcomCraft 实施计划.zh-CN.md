## 1. 产品目标

> EcomCraft 让电商运营、设计师和小店老板，**只需要一张商品图和一张想要的参考图**，就能在自己有显卡的 Windows 或 Mac 电脑（或局域网）上，得到可以直接上架的商品图和整套图；不用学模型和工作流，商品不走样，图片不出公司。

### 1.1 已确定，不再讨论

（编号 2026-10-31 由 G1–G6 改为 P1–P6，避免与 G1/G2 验收关卡混淆；G1、G2 此后只表示关卡。）

| 编号 | 决定 |
|---|---|
| P1 | **必须有显卡才能用**，不做无显卡或云端出图方案。配置不够时明确告知不支持 |
| P2 | **重点支持 Windows 和 Mac**，Linux 暂不考虑：脚本保留，不再投入和验证 |
| P3 | **模型商用许可先不作为选型条件**，默认模型只看效果和可运行性。发布前再处理（见 8.1） |
| P4 | 出图页面只保留“照参考图做”，去掉“做一张图”“出一整套”入口；整套图也由参考图驱动 |
| P5 | 简易出图要能出主图、卖点图、详情图 |
| P6 | 版本：开源核心 + 团队版（闭源扩展），按账号数收费 |

### 1.2 默认建议（用户已批准，实测后可调）

| 编号 | 决定 |
|---|---|
| D2 | 放宽“只还原感觉”红线，允许“高度相似”。边界见 1.3 |
| D3 | 首批主攻硬包装品类：个护、家电、日用。服装不进首批 |
| D5 | 最低配置：Windows NVIDIA 8GB；Mac 为 Apple 芯片 24GB 统一内存。Intel Mac 不支持；AMD 仅限 ROCm 支持列表内。数值实测后调整 |
| D6 | 先在 Windows 跑通，再适配 Mac；但默认模型选型时就要同时在 Mac 上验证 |

### 1.3 参考图的边界（写入 AGENTS.md）

**允许：** 用户自己上传参考图；生成与参考图高度相似的构图、场景、光线。

**不做：**
- 竞品链接抓取、竞品图库或推荐。
- 对外宣传“复刻竞品”，界面统一用“照参考图做”。

**必须做：**
- 文字、Logo、水印不进入成品；文字由系统重新排版。
- 含真人模特的参考图不沿用其面孔（首批直接提示不支持，见 T88）。
- 保留版权提示和海外平台加强提示（现有文案在 `simple.js:2838` 附近）。
- 参考图仍不得写入 `Data/`、商品库、归档、诊断包或备份。

用户尚未咨询律师，这是发布前待办（8.1），不阻塞开发。

### 1.4 新 MVP 验收标准

在达到最低配置的 Windows 和 Mac 电脑上：

1. 不熟悉设计的运营不看教程，从安装到完成首张图不超过 30 分钟（不含模型下载时间）。
2. 主攻品类“可直接上架”比例达到通过线（见 G1 关卡）。
3. 能导出主图和详情图。

## 3. 技术路线

### 3.1 当前路线为什么差

1. 60–120 词的文字描述保留不了精确的布局、透视和光线，生成时已是另一张图。
2. 商品位置和大小靠用户手动估。
3. 一张固定角度的商品图很难和场景机位一致。
4. 现有融合不会按场景重新打光。

调提示词解决不了，需要让模型直接“看到”参考图和商品图。

### 3.2 路线对比（按原理判断，未实测）

| 路线 | 做法 | 构图相似 | 商品保真 | 融合 | 硬件 |
|---|---|---|---|---|---|
| A 当前 | 看图写提示词，重绘，贴回 | 低 | 高 | 低 | 中 |
| B 直接替换 | 抠掉旧商品、修补背景、放入新商品 | 很高 | 很高 | 中 | 低 |
| C 多图编辑 | 参考图和商品图一起输入编辑模型 | 高 | 中 | 高 | 中高 |
| D 结构控制 | 提取深度或线稿，按结构重绘 | 中高 | 高 | 中 | 中 |
| **E 混合（目标）** | C 融合，再校验和恢复商品细节 | 高 | 高 | 高 | 中高 |

### 3.3 路线 E 的流程

1. **分析参考图：** 找到主体位置和大小，判断图位，标记文字、人物等情况。
2. **（可选）清理：** 去掉旧商品、文字、Logo。是否需要由实测决定。
3. **融合：** 参考图（或干净场景）+ 商品图 → 编辑模型。
4. **恢复商品：** 在结果里定位商品；形状和角度对得上时，贴回原商品细节。
5. **校验：** 差异过大则重试一次，仍不行就标记“商品可能走样”，不静默交付。
6. **文字：** 由 `SellingImageService` 重新排版。

**已知局限：** 模型转动商品后贴回会错位，此时不能硬贴。参考图与商品角度相差太大时，应提示用户换图或补传其他角度。

### 3.4 候选模型

| 模型 | 能力 | 配置 | 备注 |
|---|---|---|---|
| **Qwen-Image 2.1** | 文生图和编辑一体，最多 10 张参考，可输出透明通道 | 社区称 Q4_K_M 约需 6–8GB，未核实 | **首选试验对象**：用户已部署，现有蓝图的 `TextEncodeQwenImage21` 节点带 `images.image_1` 输入。官方默认 40 步，Turbo 8 步 |
| Qwen-Image-Edit-2511 | 指令编辑、多图输入，有 4 步加速 LoRA | 官方未给显存，有 GGUF | ComfyUI 有官方模板 |
| FLUX.2 klein 4B | 文生图、编辑、多图参考一体 | 官方约 13GB；FP8 少约 40%，NVFP4 少约 55% | |

**这些都没有商品替换的独立评测，效果必须实测。** 不得把本表当结论。

| 情况 | 判定（T83） | 处理 |

#### T96 安装包和签名（F77）

**目标：** 用户不需要自己装 .NET、Python、Git。

**内容：**
- Windows：安装包，桌面快捷方式。同步检查 `Desktop/`、`src/Core/Installation.cs`、启动脚本、`src/wwwroot/ecomcraft.ico`（AGENTS.md 要求）。
- Mac：`.app` 或 `.dmg`。
- **签名：** 未签名时 Windows SmartScreen 和 Mac Gatekeeper 会拦截，影响开箱即用。需要用户决定是否购买证书（Apple 开发者账号、Windows 代码签名）；没有证书时在文档写明放行步骤。
- 升级：保留 `Data/`、`Models/`、`Output/`（F45）。卸载：询问是否删除模型。

### 阶段 4

#### T97 平台和图位数据（F58 扩展）

**依赖 N06：** 第三方资料说法互相矛盾，数值必须查官方。查不到的保持 `verified: false`，不得编造。

**平台优先级：**
- 第一批（已有，先核对）：淘宝/天猫、京东、拼多多、抖音、小红书、亚马逊、Shopify、TikTok Shop、eBay。
- 第二批新增：Temu、速卖通、Shopee、Lazada、微信小店、快手。
- 第三批：SHEIN、Walmart、Etsy、1688。

**图位新增：** `first_main`（首图）、`selling`（卖点图）、`detail_page`（详情屏，含宽度、单屏高度、拼接规则）。同步 `SetRules`、`ExportRules`、`ComplianceRules`、`docs/EcomCraft 平台预设槽位设计.zh-CN.md` 和英文版。

**测试：** `ExportTests`、`ComplianceTests`。

#### T98 按图位出整套（F78）

**规则：**
- `SetRules.MaxReferences` 从 8 改到足够一套图（建议 15，5 主图 + 10 详情屏）；`BatchService.cs:365` 的总上限 20 保持。
- 上传多张参考图 → 按 `role` 分配到平台图位，用户可调整。
- 重复图位允许；缺少的图位显示为“未覆盖”。
- 每张参考默认出 1 张；候选图上可“再出一张”，单独重做不影响其他。
- 批次按图位分组显示。

**只有一张参考图时：** 只出单图，提示可再加参考图或从内置库选择（T102），不自动编造其他图位。

**套图结构（综合易可图、PicSet AI、腾讯云公开说明，不是平台官方标准）：**

| 组 | 图位 | 作用 |
|---|---|---|
| 主图 | 首图 | 吸引点击 |
| | 卖点图 | 突出核心卖点 |
| | 场景图 | 带入使用环境 |
| | 细节图 | 展示材质、做工 |
| | 白底图 | 平台要求，走 `CutoutOnly` |
| 详情页 | 首屏主视觉 | 第一印象 |
| | 卖点总览、核心卖点页 | 逐条讲清 |
| | 使用场景 | 帮助代入 |
| | 细节展示 | 解释做工 |
| | 参数和尺寸 | 只用用户填写的数据 |
| | 信任和售后 | 促成下单 |

#### T99 卖点信息和用语检查（F79）

- 出套图时填写：商品名、3–5 条卖点、参数、尺寸。可让模型根据用户文字**建议**卖点，由用户确认。
- **不得编造**参数、认证、功效。
- 按商品保存到商品库（`ProductIndex`），不用重复填。
- 用语检查放 `Prompting/ClaimRules.cs`：广告法极限词（如“最好”“第一”“国家级”），词表可配置，提示但不强制。词表须对照官方规定核对。
- 海外平台：按语言分别填写，不做机器翻译自动上架。

#### T100 卖点图和详情页版式（F80）

- 扩展 `Export/SellingImageService.cs` 和 `SellingImageRules.cs`：多种版式，文字始终由服务端绘制（已带思源黑体），**不由 AI 生成文字**。
- 文字放在图中留白区：根据 T83 的分析和商品位置选版式，避免压住商品。
- 详情页：按图位排版后，既导出分屏切片，也导出整张长图；单屏大小按 T97 规格。
- 导出：`ExportService` 增加按组（主图、详情）打包，文件名按顺序。
- 海外平台主图禁文字规则走 `ComplianceRules` 提示。

**测试：** `SellingImageRulesTests`；文字溢出、长文案、中英文。

#### T101 一套图的风格一致（F78）

**问题：** 每张参考图风格不同时，整套图会显得杂乱。

**做法：** 选项“统一色调”：以用户选定的一张为基准，对其他图做本地色调匹配（不重新生成，不改商品区域）。默认关闭，以实测结果决定是否默认开启。

#### T102 内置参考图库（F81）

- 按品类和图位提供样图，解决手里没有参考图的情况，也降低版权风险。
- **图片来源必须有权使用：** 自己生成并审核，记录来源。竞品图和未授权图片一律不进库。
- 随版本提供基础包；行业包归团队版。
- 库内图片可长期保存，与“用户参考图不落盘”是两回事，文档中分开说明。

### 阶段 5

#### 总体定位

专业模式从“参数面板”改为“精修台”。模型和采样器收进“高级”。全部功能仍只提交白名单参数，并只跑已登记的执行服务器。

#### T103 版本历史（F82）

每次修改产生新版本，不覆盖原图；可对比、回退。数据只存版本之间的关系和文件引用，规则参照项目归档（只给本人、可删除、经临时文件替换写入）；须先在 AGENTS.md 补规则。

#### T104 局部修改和商品锁定（F82）

- 复用现有局部重绘的蒙版控件（`index.html` 的 `mask-canvas`）。
- 一句话写要求（可中文），服务端转提示词。
- **默认锁定商品：** 用抠图蒙版保护商品区域，修改后贴回原商品，用户可手动解锁。
- 模型用 G1 选定的编辑模型。

#### T105 消除物体、换背景（F82）

- 消除：涂抹后移除杂物、文字、水印。
- 换背景：商品不动，换场景，可用文字或参考图。

#### T106 指令修图（F82）

“光线再暖一点”这类整图指令，走编辑模型，贴回商品。提供常用指令按钮，降低输入门槛。

#### T107 改比例和放大

把现有扩图和放大接到平台尺寸：选图位后自动计算扩图方向和放大倍数。

#### T108 P1 功能（做之前分拆成独立任务）

- **文字层：** 可编辑、可增改。
- **换色和换材质：** 必须提示“须与实物一致”（淘宝禁止货不对板）。
- **光影调整：** 方向、阴影、重新打光。
- **批量应用：** 同一修改套用到多个 SKU 或整套图。
- **PSD 导出：** 已有 F26。

**P2：** 换模特和姿势（依赖服装路线）。工作流上传和高级参数已有，保留。

## 6. 关键设计

### 6.1 新出图页面

```
第 1 步  传商品     透明 PNG / 普通照片（自动抠图）/ 商品库 / 拍照

第 3 步  挑图        收藏 / 再出一张 / 修改这张 / 按平台打包下载
```

### 6.2 新增接口（汇总）

| 接口 | 权限 | 说明 |
|---|---|---|
| `EcomCraftStudioReferenceDescribe`（扩展） | 生成权限 | 增加 `role`、`placement`、标记 |

## 8. 风险和待办

### 8.1 发布前必须处理（现在不阻塞开发）

| 事项 | 说明 |
|---|---|
| **模型许可** | Qwen-Image 2.1 官方许可写明 “FOR NON-COMMERCIAL PURPOSES ONLY”（仅研究和评估），商用须向 `model-business@notice.qwencloud.com` 申请。用户决定先不考虑。**不要在开发中反复提出，但不得在对外文档中宣称可商用。** |
| 默认模型文件 | `qwen-image-2.1-UC-Q4_K_M.gguf` 的来源和 “UC” 含义待核实 |
| 依赖许可 | `qwen3-vl`、ComfyUI-GGUF 等待核对 |
| 法律咨询 | 高度相似的边界、版本许可 |
| AI 标识 | 国内外要求须核对最新法规；可见标识 F49 未做 |

### 8.2 主要风险

| 风险 | 应对 |
|---|---|
| 所有路线都达不到通过线 | G1 关卡，不达标不开发 |
| 编辑模型改变 Logo 和文字 | T86 校验和贴回；不静默交付 |
| Mac 太慢或节点不兼容 | G1 同时测 Mac；可用独立配方；用户可调整 Mac 目标 |
| 商品角度和参考图不一致 | 提示换图；后续支持多角度商品图 |
| 贴回后比不贴回还假 | 实测对比；阈值可配置 |
| 淘宝禁止货不对板和“抠图贴图感”的 AI 图 | 保真校验；发布前核对规则原文 |
| 开发机不能编译 | 如实标注；每个 C# 任务交用户验证后才算完成 |
| 隐藏旧入口后有依赖被破坏 | T90 逐项处理；代码暂不删除 |

### 8.3 暂缓或不做

- 不做：无显卡和云端出图、竞品链接抓取、Linux 验证投入、复杂角色权限、水印限制。
- 暂缓：服装虚拟试穿、收藏偏好分析（F67）、App Mode 兼容（F27）、品牌模型训练（F17）、看图模型硬件推荐（T77）、多机实测（F28）、商品视频（F48）。
- **后续可考虑（未立项）：** 多角度商品图、同款多 SKU、图上文字多语言、候选图自动筛选（F21，T86 是其基础）。
