## 1. Background and User Story

Besides their own product photo, operators often hold **finished images from competitors**: layouts, scenes, lighting and prop styling worth borrowing. They want "an image with the same feel, but with my product", not a text description of a composition — operators cannot phrase "45-degree overhead, clear space upper-left, warm morning light".

User story: *"I upload my product photo and several reference images (say a competitor's main image, scene image and detail image); the platform generates one image per reference — each matching the feel of its own reference, but with my product."* Later: use a competitor's whole image set as references and generate one's own set in one go.

## 2. Confirmed Decisions

Confirmed with the user on 2026-10-28 (A11, see the architecture document):

| # | Decision |
|---|---|
| 1 | **Both paths are open**: path 1 "borrow the composition" (prompt reference) and path 2 "scene reference" (image-to-image) are both offered; path 2 needs the administrator to **install an extra image-to-image model** on the execution server (depends on the N10 plan), and while it is missing the option is greyed out with a reason, without affecting path 1. |
| 2 | **Restore the feel, never a 1:1 copy**: Chinese platforms generally tolerate product-image borrowing, while international platforms review image similarity more strictly. The product goal is "restore the layout, light and mood"; the interface copy, prompt composition and (path 2's) repaint strength all serve that goal, and no "replicate / same-as / 1:1" feature is built. |
| 3 | **Each reference generates its own image, never merged** (clarified by the user, 2026-10-28): every reference image maps to one independent task that produces one image matching **that reference**; there is no primary/secondary split and no merged description. References are another expansion axis for image sets ("one per reference" alongside "one per image type") and are mutually exclusive with F25 storyboards. Cap of 8 (matching storyboards), still under the 20-image total cap. |
| 4 | **Reference images are temporary, never stored** (added by the agent): they exist only inside the request and the in-memory batch, and are discarded when the task ends; they never enter the product library, the F04 project archive, diagnostics or backups (section 7). |
| 5 | **Template scope** (added by the agent): path 1 is prompt text and works for every template; path 2 needs the template to declare a `reference` image slot, initially only scene-kind templates (`scene_main` / `detail` / `model` slot kinds); the white main image needs none. |
| 6 | **Reference mode is a standalone mode where nothing else applies** (added by the user, 2026-10-28): once references are uploaded, the step-2 image type, visual style, model checkbox, brand kit, one-line description, candidate count and storyboard are all disabled; the page shows only the per-reference prompts (generated by the vision model, editable); "generate by reference" makes exactly one image per reference, always with the product-preserving scene template (P1) or the scene-reference workflow (P2). |

## 3. The Two Paths

### 3.1 Path 1: borrow the composition (prompt reference)

Each reference image goes to a vision model (MagicPrompt's vision capability; on by default per decision A5, administrators can turn it off), which produces **that reference's own** English composition description (camera, light, scene, color); it becomes that reference's prompt, shown to the user for editing (edits win), and the existing text-to-image plus product-preservation pipeline does the rest. In reference mode no product-type, style, model or brand fragments are appended.

- One reference, one task, one description — **never merged, never mixed**, so multiple references cannot fight each other.
- No new generative model is needed; the existing text-to-image pipeline works as is.
- Effect: the broad direction of layout and mood carries over, details less so — consistent with "restore the feel".
- With image description off or no usable vision model: reference mode is unavailable and the page says what is missing and how to fix it (F68); plain generation is unaffected.

### 3.2 Path 2: scene reference (image-to-image)

The reference image becomes the input of an image-to-image / image-edit workflow: "put my product into a frame with a similar feel".

- **Each task's reference is its own input**: with one-to-one mapping the single-input nature of image-to-image is a perfect fit; multi-image blending (IPAdapter-style) is left for later.
- **Depends on N10 (the image-to-image plan)**: the default model chosen in N01 is text-to-image only; execution servers need an extra image-to-image model (such as a Qwen-Image-Edit style instruction model). Templates declare `requirements` as usual, the F08 model checklist and dependency check show what is missing, and templates whose models are missing stay hidden from users (existing behavior).
- Workflow sources: commissioned from experts (N02), or the F57 standard-workflow generator extended to an image-to-image branch (both after N10).
- **Feel, not copy**: the repaint strength / reference weight is fixed by the template in a sensible (lowish) range and checked at review; the interface consistently calls path 2 "scene reference (restores the feel)".
- The template declares a `reference` slot (like the brand kit's F12 `reference_image`): `"reference": { "image": "parameter ID" }` pointing at an image parameter of the workflow snapshot; it may not point at the same parameter as `brand_kit.reference_image` (a validation error). Clients submit only image data; the server fills the parameter per task; the allowlist boundary is unchanged.

## 4. Interface and Interaction (reference mode)

1. **Reference images (optional) entry**: a new upload entry in step 2, **at most 8**, wrapping rows of thumbnails; a 9th is refused with a hint about the cap. Uploads are compressed client-side (the same 5 MB cap as gallery picks, F52) and validated server-side like any image. Each can be removed.
2. **Uploading enters reference mode**: the step-2 image type, visual style, model checkbox, brand kit, one-line description, candidate count and storyboard are **disabled and marked "not used in reference mode"**; the platform stays selectable (for later export and the international notice).
3. **Per-reference prompts**: right after upload, the vision model describes each reference in the background (list items show "describing...") and the description fills that reference's prompt field: **English is editable** (cleaned server-side, edits win), the Chinese translation is read-only; a failed description can be retried per reference. With vision off, reference mode is unavailable with a hint.
4. **Generate by reference**: the button replaces the two generate buttons and expands as products x references with **exactly one image per reference** (the candidate count does not apply); the live count hint disables the button past 20 images in total (F55).
5. **Storyboard mutual exclusion**: selling-point storyboards (F25) and references are mutually exclusive (the storyboard entry is already disabled in reference mode).
6. **Task cards**: reference-driven tasks show the **thumbnail of their reference** on the card, with the task's actual prompt unfoldable (reusing F56's `prompt_used`).
7. **Copyright notice**: fixed under the entry — references are used only to borrow layout and light; use only images you have the right to use (self-shot, licensed or restriction-free), and keep results clearly distinct from the references.
8. **Stronger notice on international platforms**: when the chosen platform's `region` is `global`, an extra notice appears — international platforms review image similarity more strictly; borrow the layout only and make sure results do not resemble the reference before listing.

## 5. Data and APIs

| API | Change |
|---|---|
| `EcomCraftStudioReferenceDescribe` (new) | `reference_images` (1-8) returns one entry per reference, `[{ index, prompt_en, prompt_zh }]` (that reference's English composition description and Chinese translation); returns `vision_disabled` when vision is off |
| `EcomCraftStudioGenerateSet` | Reference-mode parameters: `reference_images` (as above) + `reference_prompts` (one English prompt per reference, required, cleaned server-side, edits win) + optional `reference_mode` (`composition` / `scene`, for P2); reference mode always uses the product-preserving scene template — no expansion by set types — and is mutually exclusive with `shots` (submitting both returns `invalid_parameters`); tasks carry `reference_index` so the page can show the reference thumbnail |
| `EcomCraftStudioExpandPrompt` | Unchanged: AI expansion still handles the description and product type (unused in reference mode) |
| `EcomCraftStudioTemplates` | Template entries gain `reference_slot` (whether the scene-reference slot is declared, P2), so the page can control path 2's availability |
| Validation | each `reference_images` entry is an image data URL validated like a product photo, count 1-8; every `reference_prompts` entry is non-empty within the prompt length rules; template validation requires `reference.image` to be an image parameter of the snapshot and not the same parameter as the `brand_kit` slot |

## 6. Copyright and Compliance Boundary

- **Not built**: automatic scraping of competitor images, competitor image libraries or recommendations, and any "one-click replicate / same-as" feature — a red line.
- The fixed copyright notice plus the stronger international-platform notice (section 4).
- Similarity checks between results and references (warning when too close) belong under F21 automatic candidate filtering; not in this phase.
- Platform export (F58) does not know about references; AI metadata follows the existing F22 rules.

## 7. Storage and Privacy

- References **exist only inside the request and the in-memory batch**: kept in memory like product photos for the batch's lifetime (six hours), **never written under `Data/`**, and never entering the product library (F36), the project archive (F04), the candidate-cleanup registry (F39), diagnostics (F44) or backups (F45).
- Visible only to the submitter; shared queue and progress APIs never return references.
- Implementation adds the matching rule to AGENTS.md (as F04 did).

## 8. Phasing and Dependencies

| Phase | Content | Depends on | Task |
|---|---|---|---|
| P1 | Reference mode: upload (up to 8) with copyright notices, per-reference descriptions and editable prompts, all other step-2 options disabled, products x references expansion (one image per reference, fixed scene template, mutually exclusive with storyboards, 20-image cap), reference thumbnails on task cards, stronger international-platform notice | No hard dependency (A5's vision switch exists) | T61 (M) |
| P2 | Scene reference: reference mode switches to an image-to-image workflow (the template `reference` slot and validation, each task filling its own reference into the input), dependency-check display | **N10** (the image-to-image plan and model installation), N02 | T62 (L, not started) |
| P3 (reserved) | Whole-set references -> a whole set: the vision model classifies each reference's image type (white / scene / detail / model) and matches templates automatically, generating the set in one go | The vision classification accuracy after P1, N10, seed-team feedback | Not registered; see section 10 |

## 9. Acceptance Criteria (T61)

- With 3 references and 1 product: 3 images, each matching **its own** reference's composition (not a blend); a 9th upload is refused with a hint.
- After upload, the image type, visual style, model checkbox, brand kit, one-line description, candidate count and storyboard are disabled and marked; the generate buttons become "generate by reference".
- Each reference's prompt is editable: after editing the English and submitting, the task card's `prompt_used` shows the edited prompt.
- 2 products x 8 references = 16 images submits; more products or references past 20 disables the buttons with a reason; exactly one image per reference.
- Storyboards and references together prompt a choice; with vision off reference mode is unavailable with a reason, and plain generation is unaffected.
- Task cards show their reference thumbnail and actual prompt; references never appear in the product library, gallery, archive or diagnostics; nothing remains after a service restart.
- International platforms show the stronger notice; Chinese platforms show the basic copyright notice only.
- The interface is complete in both languages; the `studio-i18n` and `simple-mode` tests pass.
