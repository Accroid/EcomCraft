# SwarmUI 的设计取舍

> **语言：** [English 原文](Motivations.md) · 简体中文

本文解释 SwarmUI 在架构和工具选择上的背景。这些内容用于说明项目当时的设计动机，不代表所有项目都应采用相同选择，也不意味着相关判断适用于所有场景。

## 项目起源

SwarmUI 最初在 Stability AI 内部启动，目标是建设一套既能服务多 GPU 集群，也能满足更广泛图像生成社区需求的界面。项目后来成为面向社区独立发展的开源项目。

## 语言与模块化

服务器使用 C#，目标是在保持代码复杂度可控的同时处理多用户、多后端请求。前端使用 HTML/JavaScript；生成任务交给 ComfyUI 等独立后端执行。

项目将前端、中间层和后端尽量拆开，让扩展能够增加替代后端或新功能，而无需改动全部系统。代价是不同工具间的能力和兼容性并不总能完全一致。

## ComfyUI

ComfyUI 被选为主要集成后端，原因包括其节点系统可扩展、性能和兼容性较好，并提供图形化工作流编辑器。SwarmUI 会在此基础上增加统一的参数界面和后端管理。

## Web 前端

自定义 HTML/JavaScript 前端便于细致控制界面，也方便从其他设备远程访问。桌面程序则通过应用窗口承载本地 Web 界面，并不替代 SwarmUI 服务端或 ComfyUI 后端。
