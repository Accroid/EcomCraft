## 1. 背景与范围

MVP 完成后的试用反馈集中在简易模式的易用性和开箱可用性上，共 7 项改进，定稿为 6 个功能（F52–F57，编号已登记进架构文档和开发总表）：

| 需求 | 功能编号 | 概要 |
|---|---|---|
| R1 上传商品图 | F52 | 本机、拍照、商品库、画廊四个并列入口；画廊里已生成的作品图可选作商品图 |
| R2 平台和风格 | F53 | 「风格」改为两级「产品类型」（大类 → 子类）；视觉风格降为可选项；新增「需要模特」勾选 |
| R3 一句话描述 | F54 | AI 扩写；提示词面板中英文双语展示、都可编辑 |
| R4 候选张数 | F55 | 手动输入正整数；单次出图与一键出整套统一 20 张总上限 |
| R5 开始出图 | F56 | 提交立即入队，提示词生成移到后台，ComfyUI 尽快开跑 |
| R6 自动新建工作流 | F57 | 服务端按图片类型自动生成标准 ComfyUI 工作流并注册 |
| R7 两个出图按钮的区分 | 并入 F55 | 只改提示文案，不改行为 |

不在本次范围内：三步式流程本身、专业模式、白底主图纯抠图分支（F22）、后端安全边界（见第 9 节）、云端生成。

## 2. R1 上传商品图：四个入口（F52）

第 1 步提供四个并列入口，地位相同：

1. **本机上传**：点击或拖入，PNG / JPEG / WebP，最大 5 MB（现有行为）。
2. **拍照上传**：手机调起相机，桌面等同选择文件（F42，现有行为）。
3. **从商品库选择**：现有折叠入口提升为并列按钮；点击打开弹窗，列出本账号已入库商品（含已确认抠图与位置），缩略图选择。
4. **从画廊选择（新增）**：弹窗浏览本账号作品画廊，选一张**已生成的作品图**作为商品图，适合迭代创作。

画廊选图的约束：

- 画廊大图在客户端压缩到 5 MB 内再上传（保持现有上限）。
- 上传质量检查（F38：分辨率、模糊、商品占比）同样生效。
- 画廊作品作为商品图时不改动作品本身；入库、重命名、删除规则与普通上传一致。

**验收标准**：四个入口都能添加商品图并出现在缩略条；来源（本机 / 拍照 / 商品库 / 画廊）在缩略图上可见；从画廊选择的图超过 5 MB 时先压缩再使用。

## 3. R2 产品类型、可选风格与模特（F53）

### 3.1 产品类型（两级，主选）

原「风格」卡片改为「产品类型」两级选择：先选大类，再选子类卡片。子类带英文提示词片段，生成时并入提示词。

| 大类 | 子类 |
|---|---|
| 个护美妆 ⭐重点 | 洗发水、护手霜、身体乳、口红、香水 |
| 家用电器 | 空调、冰箱、洗衣机、电饭煲 |
| 家居日用 | 水杯餐具、收纳用品、台灯、床上用品 |
| 通用商品 | 不指定（兜底，默认不选其他时使用） |

- 数据放 `src/Extensions/EcomCraft/Templates/product-types.json`，格式与 `styles.json` 一致（中英文名称 + 英文 prompt 片段），管理员可编辑，结构校验规则与 styles 相同。
- 大类、子类数量保持 3–5 个，重点覆盖个护产品；后续增删只改数据文件。
- 选择记入浏览器本地存储（沿用现有记忆逻辑，key 更新）。

### 3.2 视觉风格（可选，第二行）

原 6 种视觉风格保留为第二行**可选项**：第一张卡片为「自动（不指定，由模型发挥）」，不选时提示词不含风格片段。

### 3.3 需要模特（勾选）

- 勾选后提示词加入模特片段（中文展示 / 英文实发各一条，内置固定文案），初版不做性别、手模等属性细分。
- 与白底主图互斥：选中白底主图时勾选框禁用并自动取消。
- 白底主图（纯抠图）以外的图片类型都可以勾选；含模特的场景使用与场景图相同的工作流蓝图，靠提示词区分。

**验收标准**：两级选择、可选风格、模特勾选的状态正确联动并反映在提示词预览；`product-types.json` 无效条目跳过并记录日志；界面中英文完整。

## 4. R3 一句话描述、AI 扩写与双语提示词（F54）

### 4.1 AI 扩写

- 描述框旁加「AI 扩写」按钮：把一句话描述（为空时按所选产品类型）交给 MagicPrompt 扩写成完整描述，按提示词面板当前语言输出并**回填提示词面板**，用户可继续修改。
- 扩写失败降级：提示「提示词服务暂不可用，可直接用一句话出图」，不阻塞出图（提交时服务端仍会组合提示词，见 F56）。

### 4.2 提示词面板（双语）

- 提示词面板提供 **中文 / English 两个语言页签**，内容由 AI 扩写同时生成两种语言；两种语言都可编辑。
- **发送规则（定稿）**：
  - 用户修改了**英文**提示词 → 直接作为引擎提示词发送，不再翻译。
  - 用户修改了**中文**提示词 → 提交时以**用户修改后的中文**为准，自动翻译成英文发送（绝不用修改前的旧版本），译文回填英文页签供查看。
  - 未修改 → 使用扩写生成的英文。
  - **发送给引擎的提示词始终是英文**（扩散模型对英文效果最好；中文能力模型接入时再扩展）。
- 状态标签实时显示：「已同步」「中文已修改 · 提交时自动翻译」「英文已修改 · 将直接发送」。
- 生成完成后，任务卡片折叠显示**实际使用的提示词**（中文展示 + 英文实发），便于核对。
- 简易模式仍然不是提示词工作台：面板只有一栏文字，没有采样器、LoRA 等专业参数。

**验收标准**：扩写生成双语并回填；改中文后提交，引擎收到的是按改后中文翻译的英文；改英文后提交，引擎收到用户输入的原文；模型不可用时一键出图仍可用；中英文界面下状态标签正确。

## 5. R4 候选张数与 R7 按钮文案（F55）

### 5.1 候选张数

- 下拉框改为数字输入：只接受正整数（1–20）；输入非法字符或超范围时即时提示「请输入正整数」/「候选张数须为 1–20 的正整数」，并禁用出图按钮。
- 服务端校验同步放宽为 1–20（现 1–4），视频仍为 1。

### 5.2 总上限 20 张（单次与整套统一）

- **「开始出图」**：候选张数 ≤ 20。
- **「一键出整套」**：预计张数 = 商品图数 × 套图类型数 × 候选张数，**总数 ≤ 20**；超过时按钮禁用并提示「预计 N 张，超过 20 张上限，请减少商品图、类型或候选张数」。
- 服务端对单次与整套统一校验总张数 ≤ 20。

### 5.3 两个按钮的区分（R7，只改文案）

- 「开始出图」提示：为当前商品 × 所选图片类型（含 / 无模特）生成 N 张候选。
- 「一键出整套」提示：为全部 N 张商品图 × 套图 M 种类型（列出类型名）× 每种 K 张，预计共 X 张（上限 20）。
- 生成逻辑不变。

**验收标准**：非法输入被拦截且按钮禁用；整套预计张数实时计算，超 20 张禁用并说明原因；服务端拒绝超限请求；白底主图直接出 1 张的提示保持正确。

## 6. R5 出图链路提速（F56）

现状：提交后服务端先等 MagicPrompt 组合提示词（最长 45 秒）才开始排队派发，用户点击到 ComfyUI 开跑之间有明显空等。

改版后：

- **提交立即入队**返回任务号（单次与整套一致）；提示词组合 / 翻译移到后台任务内完成，完成即派发 ComfyUI。
- 满足以下任一条件时跳过模型调用，任务秒级进入执行：已点过 AI 扩写且未手改、或用户改的是英文提示词。
- 状态显示三段：**正在生成提示词 → 排队中 / 执行中（含执行服务器名）→ 已完成**。
- 降级不变：提示词服务不可用或超时（后台 45 秒上限保留）时，用模板 + 产品类型默认提示词兜底，不阻塞出图。
- 一键出整套同样改造（现为先组合一次提示词再建批任务）。

**验收标准**：点击后立即得到任务反馈，无最长 45 秒的同步等待；提示词生成阶段在任务状态中可见；降级路径照常出图。

## 7. R6 标准工作流自动生成（F57）

现状：内置模板（白底主图 / 场景图 / 细节图 / 模特图）引用「约定名称」的工作流占位符，需要在每台执行服务器的 ComfyUI 中手工创建并通过审核发布后才能出图，是开箱不可用的最大门槛。

改版后：

- 扩展内置**工作流蓝图生成器**：服务端按图片类型生成标准 ComfyUI 工作流 JSON（默认大模型 + 采样器 + 解码 + 保存；保真模板带商品图输入节点，出图后由现有商品保真后处理贴回原像素）。
- **注册方式（安全边界不变）**：生成的工作流进入 WorkflowReview 注册表，标记来源「系统生成」，结构校验通过后直接发布；审核列表可见、可下架。**普通用户仍然只能提交工作流 ID，不能提交 JSON。**
- **触发时机**：
  1. 服务启动后自动检查：内置模板的工作流未发布且执行服务器在线 → 自动生成注册；
  2. 管理员设置页「初始化标准工作流」按钮 + 状态清单（已生成 / 缺模型 / 失败），作为兜底。
- **模型依赖**：蓝图使用设置中管理员指定的**默认大模型**；生成前检查目标执行服务器已安装该模型（沿用 F08 依赖检查），未安装则不注册并提示。
- **初版范围**：场景图、细节图、含模特的场景（同一蓝图，提示词区分）；白底主图无需工作流（纯抠图分支）；「模特图」模板保留人工配置路径。

**验收标准**：全新环境中登记执行服务器并装好默认模型后，不手工建工作流即可完成场景图、细节图出图；审核列表可见「系统生成」来源并可下架；缺模型时给出明确提示且不注册。

## 9. 安全边界（沿用，不因本次改版放宽）

- 客户端只能提交模板 ID、服务端发布的参数白名单和产品类型 / 风格等 ID；不提交任意 ComfyUI JSON、节点图或后端选择参数。
- 生成只发往已登记执行服务器（本机自启动 ComfyUI 或登记的局域网 ComfyUI），不回退未登记地址或云端。
- 发送给引擎的提示词固定英文；用户修改的中文提示词由服务端翻译后发送，翻译结果只作为提示词文本。
- 系统自动生成的工作流由服务端蓝图产出，走审核注册表发布、可下架；普通用户无提交 JSON 的通道。
- 进度观测不长期保存提示词或结果；候选图清理（F39）、最小披露等规则不变。

### 11.2 如何继续开发

1. 按 **T58 → T59 → T54** 顺序，一次只做一个任务。每个任务的涉及文件、依赖、验收标准、测试方式和可直接粘贴的 Claude Code 提示词在 [EcomCraft 开发总表](EcomCraft%20开发总表.xlsx)的“开发任务”工作表（K 列）。
2. 每个任务完成后的验证步骤（缺一不可）：
   - `node --check src/Extensions/EcomCraft/Studio/simple.js`（及本次改动的其他 js）
   - `node --test src/Extensions/EcomCraft/Tests/studio-i18n.test.cjs src/Extensions/EcomCraft/Tests/error-codes.test.cjs src/Extensions/EcomCraft/Tests/simple-mode.test.cjs`
   - `dotnet build src/Extensions/EcomCraft/EcomCraft.csproj -c Debug -o <临时目录>`（0 错误）
   - `dotnet test src/Extensions/EcomCraft/Tests/EcomCraft.Tests.csproj -c Debug`
   - 改了 C# 必须重启服务才生效（见 `.agents/skills/ecomcraft-build-run`）；只改前端时更新 `index.html` 的 `?v=` 后浏览器强刷即可。
3. 硬性约束（详见第 9 节与 `AGENTS.md`）：客户端只提交模板 / 参数 ID；只用已登记执行服务器；引擎提示词固定英文；新界面文字必须同步 `Studio/lang/en.js`；文档中英文同步更新。
4. 一个任务一次提交（dev 分支），提交信息格式见 `.agents/skills/dev-branch-commit`；不要提交 `src/bin`、`src/obj`、`Data/`、`Output/`。
5. 任务完成并经用户验收后：开发总表中该任务状态改为“已完成”，并同步更新本节 11.1。
