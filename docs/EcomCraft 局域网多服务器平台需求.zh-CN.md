## 1. 背景与目标

当前 EcomCraft 工作台只能调用运行 EcomCraft 的那台机器上的本机自启动 ComfyUI。

目标是把 EcomCraft 打造成局域网内的 ComfyUI 调度平台：

- 局域网内一台或多台服务器安装 ComfyUI，其他设备通过浏览器访问 EcomCraft，直接调用已审核的工作流。
- 平台自动列出各服务器的工作流，并把任务分配到负载最低、且能运行该工作流的服务器。
- 无论任务在哪台服务器执行，结果都回到用户自己的作品画廊。
- 作品默认保存在平台服务器本机，也可以存放到局域网 NAS 或其他电脑的共享文件夹。
- 后续再接入云端平台（如 RunningHub），本期只做规划。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 平台服务器 | 运行 SwarmUI + EcomCraft 的机器。文中示例为 A。 |
| 执行服务器 | 运行 ComfyUI、实际执行生成任务的机器。A 也可以同时是执行服务器。 |
| 局域网服务器 | 只安装 ComfyUI、通过网络被平台调用的机器。文中示例为 B。 |
| 所属服务器 | 工作流被发现时所在的服务器。只表示来源，不决定在哪里执行。 |
| 快照 | 审核通过时冻结保存的工作流内容、参数配置和内容指纹。 |
| 忙碌 | 某台执行服务器正在运行任务但没有排队。 |
| 繁忙 | 某台执行服务器出现排队（等待队列不为空）。 |

## 3. 已确认的关键决策

| 编号 | 决策 |
|---|---|
| D1 | 服务器接入采用**方案甲**：管理员登记 ComfyUI 地址，平台通过 ComfyUI 自带 HTTP 接口读取工作流、节点、模型和队列；局域网服务器不安装额外软件。以后如需读取任意目录或远程运维，再增加服务器端小程序（方案乙）。 |
| D2 | 工作流必须经过审核才能给普通用户调用；用户自己新建的工作流需主动提交审核。 |
| D3 | 审核能力通过权限配置，由管理员分配给账号或角色。 |
| D4 | 审核通过时冻结快照；服务器上的工作流文件变化后，需要重新审核才会使用新内容。 |
| D5 | 用户调用工作流时只看到参数表单，不展示画布；修改工作流需要编辑权限或由管理员修改。 |
| D6 | 调度采用**规则 1**：在所有能运行该工作流的执行服务器中，选择排队最少的一台，与所属服务器无关。 |
| D7 | 用户可以勾选“只在某台服务器执行”，所有用户都可使用；所选服务器繁忙而其他服务器空闲时，页面给出提示。 |
| D8 | 执行服务器在任务中掉线时直接报失败，不自动重试；提示用户可手动改派。 |
| D9 | 生成结果在平台内默认仅本人可见；用户可主动共享，共享后同组成员可见。**存储层不做隔离**：作品存放在 NAS 或其他电脑的共享文件夹时，能访问该存储的人可以看到所有人的作品。 |
| D10 | 平台支持多人同时使用，必须开启账号登录。 |
| D11 | 保留云端生成能力：调度层按“执行方”抽象设计，预留云端类型；**本期和 MVP 不开发任何云端生成功能**，规则仍禁止向云端生成服务发送请求。 |
| D12 | 作品存储位置可配置：默认存放在平台服务器本机，管理员可改为局域网 NAS 或其他电脑的共享文件夹。系统数据（账号、审核快照、配置、作品索引）固定保存在平台服务器本机。 |

## 4. 角色与权限

权限以 SwarmUI 现有的角色和权限体系为基础，新增 EcomCraft 权限，由管理员分配。

| 权限（建议 ID） | 说明 | 默认 |
|---|---|---|
| `ecomcraft_use_published_workflows`（已有） | 调用已发布工作流 | 普通用户 |
| `ecomcraft_submit_workflows` | 把自己的工作流提交审核 | 普通用户 |
| `ecomcraft_review_workflows` | 审核、发布、驳回、下架工作流，配置用户可见参数 | 管理员 |
| `ecomcraft_edit_workflows` | 修改工作流内容（修改后需重新审核） | 管理员 |
| `ecomcraft_manage_servers` | 登记、停用执行服务器 | 管理员 |
| `ecomcraft_share_results` | 把自己的作品共享给组内成员 | 普通用户 |

角色约定：

- **管理员**：拥有全部权限，并负责分配权限、管理用户组。
- **普通用户**：调用已发布工作流，提交自己的工作流审核，查看和管理自己的任务与作品。
- 审核员不设为固定角色，由管理员按需授予 `ecomcraft_review_workflows`。

## 5. 功能需求

### R1 执行服务器接入

- R1.1 管理员登记执行服务器：显示名称、地址（如 `http://192.168.1.21:8188`）、启用开关、最大并发数。优先复用 SwarmUI 已有的“按地址连接 ComfyUI”后端（`ComfyUIAPIBackend`）。
- R1.2 本机自启动 ComfyUI（`ComfyUISelfStartBackend`）同样作为执行服务器参与调度。
- R1.3 平台定期检测每台服务器：在线 / 离线、排队数、可用节点类型与模型列表（来自 `/object_info`）。
- R1.4 普通用户只看到服务器显示名称，看不到 IP 地址、端口或路径。
- R1.5 只允许连接管理员登记的地址；不做局域网网段扫描。

**验收标准**

- 登记 B 后 1 分钟内，平台显示 B 在线及其排队数。
- 关闭 B 的 ComfyUI 后，平台显示 B 离线，且不再向 B 分配任务。
- 普通用户的任何接口返回中都不包含服务器地址。

### R2 工作流发现

- R2.1 通过 ComfyUI HTTP 接口读取每台服务器保存的工作流（`/api/userdata?dir=workflows` 列表，再逐个下载）。本机服务器可继续读取工作流目录。
- R2.2 列表按服务器分组，工作流 ID 为“服务器名/工作流名”，例如“A/工作流1”“B/工作流1”，同名不冲突。ID 必须在 SwarmUI 的 `StrictFilenameClean` 清理后保持不变（不含 `/` 两侧空格、`.` 等字符），否则生成时找不到工作流。
- R2.3 后台约每 30 秒刷新一次缓存；页面请求只读缓存，不在请求线程中扫描。
- R2.4 服务器离线时，来自该服务器的待审核工作流标记为“来源离线”；已发布的快照不受影响。
- R2.5 导入时沿用现有校验：工作流结构、子图连接、正负提示词输入。不能通过校验的工作流显示原因，不能提交发布。

**验收标准**

- A、B 各保存一个同名工作流，审核页能分别看到“A/工作流1”和“B/工作流1”。
- 在 B 的 ComfyUI 中新保存一个工作流，1 分钟内出现在待审核列表。

### R3 工作流审核与快照

状态流转：

```
服务器上发现 / 用户提交 → 待审核 → 通过 → 已发布 → 下架
                              └→ 驳回（附原因）
已发布 + 来源文件变化 → 待重新审核（用户仍使用旧快照）
```

- R3.1 服务器上自动发现的工作流默认为“待审核”，普通用户不可见。
- R3.2 用户在 ComfyUI 中保存自己的工作流后，在 EcomCraft 中选择并“提交审核”，可填写说明。
- R3.3 审核人可以：预览工作流参数、配置用户可见参数、通过、驳回（必须填写原因）、下架。
- R3.4 **用户可见参数配置**：审核人逐个决定参数是否显示，并设置中文显示名、默认值、取值范围或可选项；未显示的参数固定使用快照中的值。
- R3.5 审核页显示“可运行服务器”，例如“A、B”或“仅 A（B 缺少 xxx 模型 / yyy 节点）”。
- R3.6 通过时保存快照：转换后的执行图、参数配置、内容指纹、来源服务器、审核人、审核时间。
- R3.7 平台检测到来源文件内容变化时，提示审核人重新审核；新版本通过前，用户继续使用旧快照。
- R3.8 用户可以查看自己提交的工作流状态和驳回原因。

**验收标准**

- 未审核的工作流不会出现在普通用户的选择列表，也不能通过接口调用。
- 在 ComfyUI 中修改已发布工作流后，用户调用结果仍按旧快照执行，审核页出现“待重新审核”。

### R4 调用工作流

- R4.1 用户只能从“已发布”列表中选择工作流。
- R4.2 选中后自动显示审核人配置的参数表单，直接提交，不展示画布或原始节点图。
- R4.3 模型类参数的可选项只包含当前用户有权使用、且至少一台可运行服务器上存在的模型。
- R4.4 客户端只能提交工作流 ID、已发布参数和普通生成参数；服务端逐项校验，拒绝任意 ComfyUI JSON、后端选择器和未发布参数。
- R4.5 参考图等输入在提交时上传到被选中的执行服务器（`/upload/image`），再提交任务。

### R5 调度

- R5.1 **规则 1**：先筛选出具备该工作流全部所需节点类型和模型的在线服务器，再选排队数最少的一台；排队数相同时，选最近完成任务最早的一台。
- R5.2 排队数 = 该服务器 ComfyUI 队列中的运行和等待任务数（含其他人直接在该 ComfyUI 上提交的任务）+ 平台已分配但尚未提交的任务数。
- R5.3 有任务在执行但未排队的服务器显示“忙碌”（黄色指示灯），出现排队的服务器显示“繁忙”（红色指示灯）。页面实时显示每台服务器的排队数，例如“A：繁忙（排队 3）｜B：忙碌（执行 1，排队 0）｜C：空闲（排队 0）”。
- R5.4 用户勾选“只在某台服务器执行”时不改派，任务在该服务器排队。所选服务器繁忙而另一台可运行服务器空闲时，提示“建议取消限定”。
- R5.5 没有可运行的服务器时，明确提示原因（全部离线，或缺少哪些节点 / 模型），不提交任务。
- R5.6 结果标注实际执行服务器。
- R5.7 一键套图与批量（F03）展开为多个独立任务：每张商品图 × 套图中的每种图片类型各一个任务，每个任务分别按规则 1 调度，因此可以在多台服务器上并行。单个任务失败不影响其他任务，可单独重试；整体取消会停止还在排队的任务，正在执行的任务会完成。

### R6 失败处理

- R6.1 执行服务器在任务执行中掉线或连接中断时，任务直接报失败，不自动重试。
- R6.2 失败提示中提供“改派到其他服务器”按钮；用户点击后，按 R5 重新选择服务器并提交。
- R6.3 返回给浏览器的错误不包含异常堆栈、服务器地址、提示词原文或原始节点图。

### R7 作品画廊

- R7.1 无论在哪台服务器执行，结果都传回平台服务器，保存到当前用户的输出目录，并显示在作品画廊。设置了作品库位置后，结果先保存在本机，再同步到作品库（见 R11）。
- R7.2 画廊显示工作流名、实际执行服务器、生成时间。图片和视频都支持。
- R7.3 作品在平台内默认仅本人可见。用户可对单个作品选择“共享到组”，同组成员可见；可随时取消共享。（第二阶段）
- R7.4 平台内的可见性不延伸到存储层：作品存放在共享存储时，存储本身不按用户隔离（见 D9、R11）。

### R8 任务队列

- R8.1 队列页显示每台执行服务器的状态、排队数和当前任务进度。
- R8.2 用户只能看到自己任务的详情，只能结束自己的任务；其他人的任务只显示数量，不显示提示词和参数。

### R9 多人使用

- R9.1 开启账号登录（`UserAuthorization.AuthorizationRequired`），每人一个账号。
- R9.2 每人排队上限复用 SwarmUI 角色已有的 `MaxQueued` 设置，由管理员按角色配置。
- R9.4 按人限流：套图和批量任务中，每人同时执行的任务数不超过其角色的 `MaxT2ISimultaneous` 与 4 中的较小值；其余任务在平台内排队，不占用执行服务器，避免一个人占满所有显卡。`MaxQueued` 仍按张数限制总排队量。
- R9.3 用户组（第二阶段）：管理员维护用户组，用于共享画廊和工作流分组授权。

### R10 云端对接（仅预留能力，本期不开发）

- R10.1 调度层（步骤 4）按统一的“执行方”抽象实现，类型分为：本机 ComfyUI、局域网 ComfyUI、云端 ComfyUI（如 RunningHub、Comfy Cloud）、云端模型 API（国内外图像生成服务）。本期只实现前两类，后两类只保留类型和接口位置。
- R10.2 模板可以挂多个执行方案（本地方案、云端方案），用户看到的字段相同；每个方案都需审核。本期只实现本地方案。
- R10.3 生成流程按“本地预处理 → 生成 → 本地后处理”三段实现。将来接入云端时只把“生成”一步交给云端；抠图、商品蒙版和商品保真合成始终在本地完成。
- R10.4 云端接入时再补充：管理员配置 API Key（只保存在服务端）、数据外发同意、团队预算与每人额度、费用记录、结果下载回本地画廊。
- R10.5 局域网服务器全忙时不自动转到云端（会产生费用）；将来最多提示用户，由用户确认。
- R10.6 云端阶段开始前，必须先修改 AGENTS.md、README 和本文中“不得向云端生成服务发送请求”的规则。

### R11 作品存储

- R11.1 管理员可分别设置**作品库位置**（商品原图、生成结果）和**导出位置**（导出包）。默认都在平台服务器本机。
- R11.2 支持的位置：本机目录；Windows 的 UNC 路径（如 `\\NAS\share\EcomCraft`）；Linux / macOS 由系统挂载后的目录。不支持映射盘符（后台服务看不到登录用户映射的盘符）。
- R11.3 平台不实现 SMB 协议、不保存 NAS 密码；访问共享存储所需的认证由操作系统完成（部署文档说明配置方法）。
- R11.4 只有管理员能修改存储位置。保存时检测：路径可写、剩余空间、读写速度；检测失败时不保存并说明原因。客户端永远不能提交文件路径。
- R11.5 **先写本地，再同步**：生成结果先保存到平台服务器本机，后台异步复制到作品库位置，失败时排队重试。共享存储离线不影响生成，画廊对未同步的作品显示“待同步”。
- R11.6 作品索引和缩略图保存在平台服务器本机；画廊浏览不扫描共享存储，打开原图时再读取。
- R11.7 修改作品库位置后，新作品写入新位置；旧作品留在原位置并仍可浏览。提供可选的“迁移旧作品”操作：复制、校验后再删除原文件，显示进度，可中途取消。不做静默搬移。
- R11.8 导出时用户可选择“下载 zip”或“导出到共享文件夹”（导出位置由管理员设置）。
- R11.9 系统数据（账号数据库、审核快照、模板与平台预设配置、作品索引）固定保存在平台服务器本机的 `Data/` 下，不放到共享存储。

**验收标准**

- 作品库位置设为 NAS 后，新生成的作品出现在 NAS 对应目录中。
- 生成过程中断开 NAS，生成照常完成，画廊显示“待同步”；NAS 恢复后自动同步完成。
- 普通用户的任何接口都不能设置或读取存储路径。

## 6. 非功能需求

### 安全

- 只向管理员登记的执行服务器发送请求；不得连接未登记地址；云端阶段之前不得向任何云端生成服务发送请求。
- ComfyUI 本身没有登录验证。部署文档必须说明：局域网服务器的防火墙只对平台服务器开放 ComfyUI 端口；平台服务器开启账号登录；不要把任何服务器暴露到公网。
- 继续遵守最小披露：普通用户接口不返回服务器地址、原始工作流、其他用户的任务 ID、会话 ID 或密钥。
- 作品存放在共享存储时，部署文档必须说明：能访问共享目录的人可以看到所有人的作品（D9）；如需限制，应在 NAS 上只给平台服务账号授权。普通用户接口不返回存储路径。

### 性能

- 工作流发现、服务器状态检测在后台执行并缓存，接口请求不做阻塞式扫描。
- 访问执行服务器的每个请求都设置超时（状态检测建议 3 秒，工作流下载建议 10 秒）。

### 可靠性

- 单台服务器离线不影响其他服务器的发现和调度。
- 平台重启后，审核状态、快照和服务器登记信息不丢失（保存在 `Data/EcomCraft/` 下）。
- 本机自启动的 ComfyUI 不得在平台退出后残留（F72）：平台被强制结束、崩溃或断电时，它启动的 ComfyUI 会继续运行，占用内存、显存和端口，下次启动又另开一个。平台每次启动 ComfyUI 时记录进程号和启动时间（只记这两项，保存在数据目录），下次启动先结束仍在运行且启动时间一致的旧进程；启动它的平台仍在运行时不结束（防止误开第二个平台时关掉第一个的 ComfyUI），进程号已被其他程序复用、无权结束或已退出时跳过，不影响启动。

## 7. 开发阶段与任务

### 第一阶段：局域网多服务器跑通

## 8. 对现有项目规则的变更

原 AGENTS.md 和 README 规定工作台只允许本机自启动 ComfyUI，不得转到远程或云端。第一阶段步骤 1 已把这条规则改为：

> 生成请求只能发送到管理员登记的执行服务器（本机自启动 ComfyUI 和已登记的局域网 ComfyUI）；不得连接未登记地址；云端对接完成并经确认之前，不得向任何云端生成服务发送请求。

AGENTS.md、README 和工作流文档已同步修改。

步骤 1–2 的实现说明：

- 执行服务器的显示名称取后端 Title，未设置时为 `本机 #编号` / `服务器 #编号`。
- 地址限制：只认回环、私有网段 IP 和局域网主机名（不含点，或以 `.local`、`.lan`、`.home.arpa`、`.internal` 结尾）；其他地址的 `ComfyUI API By URL` 后端不会被工作台使用。
- 标准工作台模式（不选工作流）的节点图由 SwarmUI 生成，依赖 SwarmUI 配套节点，因此只分配给本机自启动后端或已安装 `SwarmKSampler` 等节点的服务器；原生工作流按其自身节点和模型依赖分配；手动发布的 SwarmUI 工作流要求服务器具备其全部节点类型。
- 提交前的服务器检查从“有空闲服务器”改为“有在线服务器”，所有服务器都忙时任务进入 SwarmUI 队列等待，不再直接拒绝。`local_backends_observed` 字段含义相应改为在线服务器数，字段名为兼容前端保留。
- 本期调度仍使用 SwarmUI 原有的分配逻辑（在能运行的服务器中选当前占用最少的一台），尚未计入其他人直接提交到 ComfyUI 的排队数；完整的规则 1 在步骤 4 实现。
- 发现缓存由扩展启动的后台任务约每 30 秒刷新一次，没有人打开页面时也会刷新，因此新保存或修改的工作流无需手动刷新即可进入审核列表；页面请求在缓存过期时也会触发刷新。
- 工作流 ID 以执行服务器的显示名称为前缀。登记服务器时应先设置名称（后端 Title），审核后不要修改：修改名称或未设名称时后端编号变化，会使该服务器上所有工作流以新 ID 回到待审核，原 ID 的已发布快照仍可使用但显示“来源缺失”。改用不随名称变化的稳定 ID 在步骤 4 处理。

步骤 3 的实现说明：

- 新增权限 `ecomcraft_submit_workflows`（默认普通用户）和 `ecomcraft_review_workflows`（默认管理员）。`ecomcraft_edit_workflows`、`ecomcraft_manage_servers`、`ecomcraft_share_results` 留到用到时再注册；目前修改工作流内容在 ComfyUI 中进行，服务器登记沿用 SwarmUI 后端管理。
- 发现的工作流只作为审核候选，不再直接进入用户可选列表。审核通过时保存快照（来源画布、转换后的执行图、发现时的参数绑定、审核人的参数配置、内容指纹、来源服务器、审核人、审核时间），用户调用的是快照。审核记录保存在 `Data/EcomCraft/workflow-reviews.json`，平台重启后不丢失；文件损坏时改名为 `.damaged-时间` 保留并从空记录开始，文件无法读取时拒绝保存以免覆盖。
- 内容指纹覆盖转换后的执行图、参数绑定和工作流内保存的值，不包含各服务器公布的模型选项，因此只在工作流本身变化时变化，安装新模型不会触发重新审核。
- 状态：待审核、已发布、待重新审核（已发布但来源已变化，用户继续用旧快照）、已驳回（来源再次变化或重新提交后回到待审核）、已下架（重新通过前保持下架）、无法导入（显示原因，不能提交或发布）。已发布工作流的新版本被驳回时，仍显示已发布并保留驳回原因。
- 审核人可以对每个参数设置是否显示、显示名、默认值、取值范围（只能在工作流原有范围内收窄）和下拉可选项（原有选项的子集）。创作描述、排除内容、宽度和高度是页面固定字段，不能隐藏。隐藏的参数固定使用快照中的默认值；隐藏的种子保持固定值，填 `-1` 时每次随机。已发布工作流可以只修改参数配置；来源暂时不可用时基于快照修改。
- 快照保留来源画布，有 SwarmUI 工作流读取权限的账号仍可在原生 ComfyUI 编辑器中打开它；审核和提交接口不返回画布。
- 被隐藏的模型参数固定使用快照中的模型，当前账号无权使用该模型时，工作流不出现在其可选列表中。
- 两名审核人同时处理同一工作流时，后保存的一方会收到“状态刚被其他人修改”的提示，不会覆盖。
- 驳回原因只返回给提交人和审核人；提交列表不返回其他人的提交人和说明。审核接口返回参数定义和缺失的节点/模型名称，不返回原始节点图或服务器地址。
- 下拉框和模型参数的可选项在审核通过时冻结；R4.3 要求的“只列出至少一台可运行服务器上存在的模型”在步骤 4 处理。
- 升级说明：升级前自动发现并直接可用的原生工作流，升级后需要审核通过才会重新出现在用户列表中。管理员在 SwarmUI 工作流编辑器中启用 **Enable in Simple** 的工作流不受影响。
- 内容指纹基于转换后的执行图计算。以后升级工作流转换逻辑时，已发布的工作流可能全部显示为“待重新审核”；重新审核前用户继续使用旧快照，出图不受影响。

步骤 4 的实现说明：

- 调度按“执行方”抽象实现（`ExecutorKind`：本机 ComfyUI、局域网 ComfyUI、云端 ComfyUI、云端模型 API），后两类只保留类型，不产生执行方，也不发送任何请求。
- 提交时读取各在线服务器的 ComfyUI 队列（每台 3 秒超时，并行读取；读不到的服务器视为离线），按规则 1 选出一台，并把服务器 ID 写入请求的内部元数据；后端匹配时只允许这台服务器执行，服务器正忙时任务在 SwarmUI 中排队等待。一次提交的多张图片分配到同一台服务器。
- 排队数 = ComfyUI 运行数 + 等待数 + 平台已分配给该服务器、但尚未被 SwarmUI 占用的任务数。已被 SwarmUI 占用的任务视为已在 ComfyUI 队列中；占用后到提交进 ComfyUI 之间的几秒内会少算，属于已知的估算误差。
- 限定服务器（`execution_server_id`）时不改派：该服务器离线或缺依赖直接报错（`execution_server_unavailable`）；它有排队而另一台可运行的服务器空闲时，响应附带 `server_hint`。没有可运行的服务器时返回 `no_execution_server`，区分“全部离线”和“各服务器缺少的节点 / 模型”（每台最多 3 项）。原有的 `local_unavailable` 和 `workflow_dependencies_missing` 不再由生成接口返回。
- R4.3：原生工作流模型下拉框只列出账号有权使用、且至少一台在线服务器上存在的模型。R4.5：参考图由 SwarmUI 的 ComfyUI 后端上传到实际执行的服务器，未改代码，待实测确认。
- 结果标注：响应包含 `execution_server`（显示名称），服务器 ID 和名称同时写入作品元数据，供步骤 5 的画廊显示。
- 队列接口新增 `assigned`、`queue` 和 `load`（`idle` / `working` / `congested`），`busy` 改为等同于 `congested`，不再使用“排队超过 2 个”的阈值。

步骤 5 的实现说明：

- 后台任务结束后，平台在内存中保留结果 15 分钟（每个账号最多 50 条），只含任务 ID、成功或失败、已转成中文的失败原因、错误码和执行服务器名称，不含提示词、参数、图片或节点图。失败原因经现有的错误转换处理，不含异常堆栈、地址、提示词或节点图（R6.3）。提交后几秒内就失败的任务，提交请求直接返回错误。
- 队列接口新增 `finished_tasks`，只列当前账号的结果（`id`、`state`、`error`、`error_id`、`execution_server`）。
- 任务失败时，工作台显示失败原因和“改派到其他服务器”按钮；点击后用同一请求重新提交，去掉服务器限定，由规则 1 重新选择。平台不会自动重试（R6.1）。请求只保存在页面内存中，刷新页面后只显示失败原因、不再提供改派；结果不确定（`generation_uncertain`）时不提供改派，避免重复生成。
- 画廊从作品元数据读取工作流 ID 和执行服务器名称，显示在作品卡片的时间下方；标准工作台生成的作品显示“标准工作台”，升级前的作品不显示。
- 执行中的服务器掉线后，SwarmUI 需要多久判定任务失败尚未实测，见 V5。

步骤 7 的实现说明：

- 管理员（`edit_server_settings` 权限）在画廊页的“存储设置”中填写作品库位置和导出位置，留空表示只保存在平台服务器本机。保存时服务端检查：完整路径、不在 `Data/` 或输出目录内（也不包含它们）；位置可创建并写入一个 8 MB 测试文件；能读取剩余空间时须不少于 1 GB；记录写入速度。Windows 上映射的网络盘符被拒绝。检测最长 30 秒，超时视为位置不可用。任何一项失败都不保存。设置保存在 `Data/EcomCraft/storage.json`。
- 只有工作台生成的作品会同步。生成完成后，作品已由 SwarmUI 保存在本机输出目录，平台把它们加入同步队列（`Data/EcomCraft/storage-sync.json`，重启不丢），后台每 5 秒处理到期的项目：先复制到同目录的临时文件，核对大小后改名，元数据旁文件（`.swarm.json`）一并复制。作品库结构为 `作品库/<账号>/<与输出目录相同的相对路径>`。失败后按 10 秒起翻倍、最长 10 分钟重试；作品库离线不影响生成。
- 本期保留本机副本：画廊、缩略图和打开原图都读取本机文件，不扫描共享存储（R11.6）。同步完成后清理本机副本留给后续任务。
- 画廊为尚未复制完成的作品显示“待同步”。普通用户接口 `EcomCraftStoragePending` 只返回本人作品的画廊相对路径，不返回任何存储位置；管理员接口为 `EcomCraftStorageSettings`、`EcomCraftStorageSave` 和 `EcomCraftStorageMigrate`。
- 修改作品库位置后，新作品写入新位置，已排队的作品仍写入排队时的位置；旧位置的作品保留原处。管理员可以选择“迁移旧作品”：逐个文件复制、用 SHA-256 校验后再删除原文件，显示进度，可随时停止；失败的文件留在原处。
- 导出位置在平台导出（T11）中使用：用户在简易模式第 3 步选择“导出到共享文件夹”时，作品按平台规格处理后写入 `导出位置/<账号>/<时间-平台>/<商品>/`；也可以打包下载 zip（R11.8）。
