# EcomCraft 局域网多服务器平台需求

> **语言：** 简体中文（本文为开发需求文档，暂无英文版）
>
> **状态：** 开发中（第一阶段步骤 1–2 代码完成） · **版本：** v1.1 · **日期：** 2026-10-26
>
> 后续开发以本文为准。需求变更时，先修改本文并在文末“变更记录”中登记，再修改代码。

## 1. 背景与目标

当前 EcomCraft 工作台只能调用运行 EcomCraft 的那台机器上的本机自启动 ComfyUI。

目标是把 EcomCraft 打造成局域网内的 ComfyUI 调度平台：

- 局域网内一台或多台服务器安装 ComfyUI，其他设备通过浏览器访问 EcomCraft，直接调用已审核的工作流。
- 平台自动列出各服务器的工作流，并把任务分配到负载最低、且能运行该工作流的服务器。
- 无论任务在哪台服务器执行，结果都回到用户自己的作品画廊。
- 后续再接入云端平台（如 RunningHub），本期只做规划。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 平台服务器 | 运行 SwarmUI + EcomCraft 的机器。文中示例为 A。 |
| 执行服务器 | 运行 ComfyUI、实际执行生成任务的机器。A 也可以同时是执行服务器。 |
| 局域网服务器 | 只安装 ComfyUI、通过网络被平台调用的机器。文中示例为 B。 |
| 所属服务器 | 工作流被发现时所在的服务器。只表示来源，不决定在哪里执行。 |
| 快照 | 审核通过时冻结保存的工作流内容、参数配置和内容指纹。 |
| 繁忙 | 某台执行服务器排队超过 2 条任务。 |

## 3. 已确认的关键决策

| 编号 | 决策 |
|---|---|
| D1 | 服务器接入采用**方案甲**：管理员登记 ComfyUI 地址，平台通过 ComfyUI 自带 HTTP 接口读取工作流、节点、模型和队列；局域网服务器不安装额外软件。以后如需读取任意目录或远程运维，再增加服务器端小程序（方案乙）。 |
| D2 | 工作流必须经过审核才能给普通用户调用；用户自己新建的工作流需主动提交审核。 |
| D3 | 审核能力通过权限配置，由管理员分配给账号或角色。 |
| D4 | 审核通过时冻结快照；服务器上的工作流文件变化后，需要重新审核才会使用新内容。 |
| D5 | 用户调用工作流时只看到参数表单，不展示画布；修改工作流需要编辑权限或由管理员修改。 |
| D6 | 调度采用**规则 1**：在所有能运行该工作流的执行服务器中，选择排队最少的一台，与所属服务器无关。 |
| D7 | 用户可以勾选“只在某台服务器执行”，所有用户都可使用；所选服务器繁忙而其他服务器空闲时，页面给出提示。 |
| D8 | 执行服务器在任务中掉线时直接报失败，不自动重试；提示用户可手动改派。 |
| D9 | 生成结果默认仅本人可见；用户可主动共享，共享后同组成员可见。 |
| D10 | 平台支持多人同时使用，必须开启账号登录。 |
| D11 | 云端对接只做规划和接口预留，等本地局域网调用调试完成后再开发。 |

## 4. 角色与权限

权限以 SwarmUI 现有的角色和权限体系为基础，新增 EcomCraft 权限，由管理员分配。

| 权限（建议 ID） | 说明 | 默认 |
|---|---|---|
| `ecomcraft_use_published_workflows`（已有） | 调用已发布工作流 | 普通用户 |
| `ecomcraft_submit_workflows` | 把自己的工作流提交审核 | 普通用户 |
| `ecomcraft_review_workflows` | 审核、发布、驳回、下架工作流，配置用户可见参数 | 管理员 |
| `ecomcraft_edit_workflows` | 修改工作流内容（修改后需重新审核） | 管理员 |
| `ecomcraft_manage_servers` | 登记、停用执行服务器 | 管理员 |
| `ecomcraft_share_results` | 把自己的作品共享给组内成员 | 普通用户 |

角色约定：

- **管理员**：拥有全部权限，并负责分配权限、管理用户组。
- **普通用户**：调用已发布工作流，提交自己的工作流审核，查看和管理自己的任务与作品。
- 审核员不设为固定角色，由管理员按需授予 `ecomcraft_review_workflows`。

## 5. 功能需求

### R1 执行服务器接入

- R1.1 管理员登记执行服务器：显示名称、地址（如 `http://192.168.1.21:8188`）、启用开关、最大并发数。优先复用 SwarmUI 已有的“按地址连接 ComfyUI”后端（`ComfyUIAPIBackend`）。
- R1.2 本机自启动 ComfyUI（`ComfyUISelfStartBackend`）同样作为执行服务器参与调度。
- R1.3 平台定期检测每台服务器：在线 / 离线、排队数、可用节点类型与模型列表（来自 `/object_info`）。
- R1.4 普通用户只看到服务器显示名称，看不到 IP 地址、端口或路径。
- R1.5 只允许连接管理员登记的地址；不做局域网网段扫描。

**验收标准**

- 登记 B 后 1 分钟内，平台显示 B 在线及其排队数。
- 关闭 B 的 ComfyUI 后，平台显示 B 离线，且不再向 B 分配任务。
- 普通用户的任何接口返回中都不包含服务器地址。

### R2 工作流发现

- R2.1 通过 ComfyUI HTTP 接口读取每台服务器保存的工作流（`/api/userdata?dir=workflows` 列表，再逐个下载）。本机服务器可继续读取工作流目录。
- R2.2 列表命名为“服务器名 / 工作流名”，例如“A / 工作流1”“B / 工作流1”，同名不冲突。
- R2.3 后台约每 30 秒刷新一次缓存；页面请求只读缓存，不在请求线程中扫描。
- R2.4 服务器离线时，来自该服务器的待审核工作流标记为“来源离线”；已发布的快照不受影响。
- R2.5 导入时沿用现有校验：工作流结构、子图连接、正负提示词输入。不能通过校验的工作流显示原因，不能提交发布。

**验收标准**

- A、B 各保存一个同名工作流，审核页能分别看到“A / 工作流1”和“B / 工作流1”。
- 在 B 的 ComfyUI 中新保存一个工作流，1 分钟内出现在待审核列表。

### R3 工作流审核与快照

状态流转：

```
服务器上发现 / 用户提交 → 待审核 → 通过 → 已发布 → 下架
                              └→ 驳回（附原因）
已发布 + 来源文件变化 → 待重新审核（用户仍使用旧快照）
```

- R3.1 服务器上自动发现的工作流默认为“待审核”，普通用户不可见。
- R3.2 用户在 ComfyUI 中保存自己的工作流后，在 EcomCraft 中选择并“提交审核”，可填写说明。
- R3.3 审核人可以：预览工作流参数、配置用户可见参数、通过、驳回（必须填写原因）、下架。
- R3.4 **用户可见参数配置**：审核人逐个决定参数是否显示，并设置中文显示名、默认值、取值范围或可选项；未显示的参数固定使用快照中的值。
- R3.5 审核页显示“可运行服务器”，例如“A、B”或“仅 A（B 缺少 xxx 模型 / yyy 节点）”。
- R3.6 通过时保存快照：转换后的执行图、参数配置、内容指纹、来源服务器、审核人、审核时间。
- R3.7 平台检测到来源文件内容变化时，提示审核人重新审核；新版本通过前，用户继续使用旧快照。
- R3.8 用户可以查看自己提交的工作流状态和驳回原因。

**验收标准**

- 未审核的工作流不会出现在普通用户的选择列表，也不能通过接口调用。
- 在 ComfyUI 中修改已发布工作流后，用户调用结果仍按旧快照执行，审核页出现“待重新审核”。

### R4 调用工作流

- R4.1 用户只能从“已发布”列表中选择工作流。
- R4.2 选中后自动显示审核人配置的参数表单，直接提交，不展示画布或原始节点图。
- R4.3 模型类参数的可选项只包含当前用户有权使用、且至少一台可运行服务器上存在的模型。
- R4.4 客户端只能提交工作流 ID、已发布参数和普通生成参数；服务端逐项校验，拒绝任意 ComfyUI JSON、后端选择器和未发布参数。
- R4.5 参考图等输入在提交时上传到被选中的执行服务器（`/upload/image`），再提交任务。

### R5 调度

- R5.1 **规则 1**：先筛选出具备该工作流全部所需节点类型和模型的在线服务器，再选排队数最少的一台；排队数相同时，选最近完成任务最早的一台。
- R5.2 排队数 = 该服务器 ComfyUI 队列中的运行和等待任务数（含其他人直接在该 ComfyUI 上提交的任务）+ 平台已分配但尚未提交的任务数。
- R5.3 排队超过 2 条的服务器显示“繁忙”。页面实时显示每台服务器的排队数，例如“A：繁忙（排队 3）｜B：空闲（排队 0）”。
- R5.4 用户勾选“只在某台服务器执行”时不改派，任务在该服务器排队。所选服务器繁忙而另一台可运行服务器空闲时，提示“建议取消限定”。
- R5.5 没有可运行的服务器时，明确提示原因（全部离线，或缺少哪些节点 / 模型），不提交任务。
- R5.6 结果标注实际执行服务器。

### R6 失败处理

- R6.1 执行服务器在任务执行中掉线或连接中断时，任务直接报失败，不自动重试。
- R6.2 失败提示中提供“改派到其他服务器”按钮；用户点击后，按 R5 重新选择服务器并提交。
- R6.3 返回给浏览器的错误不包含异常堆栈、服务器地址、提示词原文或原始节点图。

### R7 作品画廊

- R7.1 无论在哪台服务器执行，结果都传回平台服务器，保存到当前用户的输出目录，并显示在作品画廊。
- R7.2 画廊显示工作流名、实际执行服务器、生成时间。图片和视频都支持。
- R7.3 作品默认仅本人可见。用户可对单个作品选择“共享到组”，同组成员可见；可随时取消共享。（第二阶段）

### R8 任务队列

- R8.1 队列页显示每台执行服务器的状态、排队数和当前任务进度。
- R8.2 用户只能看到自己任务的详情，只能结束自己的任务；其他人的任务只显示数量，不显示提示词和参数。

### R9 多人使用

- R9.1 开启账号登录（`UserAuthorization.AuthorizationRequired`），每人一个账号。
- R9.2 每人排队上限复用 SwarmUI 角色已有的 `MaxQueued` 设置，由管理员按角色配置。
- R9.3 用户组（第二阶段）：管理员维护用户组，用于共享画廊和工作流分组授权。

### R10 云端对接（仅规划，本期不开发）

- 在调度层预留统一的“执行服务器”抽象，类型分为本机 ComfyUI、局域网 ComfyUI、云端平台。
- 云端接入时需要：管理员配置 API Key、把云端工作流登记为平台工作流并走审核、用量与费用记录、结果下载回本地画廊。
- 局域网服务器全忙时是否允许自动转到云端（会产生费用），在云端阶段单独确认。默认不自动转云端。

## 6. 非功能需求

### 安全

- 只向管理员登记的执行服务器发送请求；不得连接未登记地址；云端阶段之前不得向任何云端生成服务发送请求。
- ComfyUI 本身没有登录验证。部署文档必须说明：局域网服务器的防火墙只对平台服务器开放 ComfyUI 端口；平台服务器开启账号登录；不要把任何服务器暴露到公网。
- 继续遵守最小披露：普通用户接口不返回服务器地址、原始工作流、其他用户的任务 ID、会话 ID 或密钥。

### 性能

- 工作流发现、服务器状态检测在后台执行并缓存，接口请求不做阻塞式扫描。
- 访问执行服务器的每个请求都设置超时（状态检测建议 3 秒，工作流下载建议 10 秒）。

### 可靠性

- 单台服务器离线不影响其他服务器的发现和调度。
- 平台重启后，审核状态、快照和服务器登记信息不丢失（保存在 `Data/EcomCraft/` 下）。

## 8. 对现有项目规则的变更

原 AGENTS.md 和 README 规定工作台只允许本机自启动 ComfyUI，不得转到远程或云端。第一阶段步骤 1 已把这条规则改为：

> 生成请求只能发送到管理员登记的执行服务器（本机自启动 ComfyUI 和已登记的局域网 ComfyUI）；不得连接未登记地址；云端对接完成并经确认之前，不得向任何云端生成服务发送请求。

AGENTS.md、README 和工作流文档已同步修改。

步骤 1–2 的实现说明：

- 执行服务器的显示名称取后端 Title，未设置时为 `本机 #编号` / `服务器 #编号`。
- 地址限制：只认回环、私有网段 IP 和局域网主机名（不含点，或以 `.local`、`.lan`、`.home.arpa`、`.internal` 结尾）；其他地址的 `ComfyUI API By URL` 后端不会被工作台使用。
- 标准工作台模式（不选工作流）的节点图由 SwarmUI 生成，依赖 SwarmUI 配套节点，因此只分配给本机自启动后端或已安装 `SwarmKSampler` 等节点的服务器；原生工作流按其自身节点和模型依赖分配；手动发布的 SwarmUI 工作流要求服务器具备其全部节点类型。
- 提交前的服务器检查从“有空闲服务器”改为“有在线服务器”，所有服务器都忙时任务进入 SwarmUI 队列等待，不再直接拒绝。`local_backends_observed` 字段含义相应改为在线服务器数，字段名为兼容前端保留。
- 本期调度仍使用 SwarmUI 原有的分配逻辑（在能运行的服务器中选当前占用最少的一台），尚未计入其他人直接提交到 ComfyUI 的排队数；完整的规则 1 在步骤 4 实现。
