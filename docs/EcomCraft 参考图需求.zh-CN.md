## 1. 背景与用户故事

运营手里除了自己的商品原图，常常还有**竞品的成品图**：构图、场景、光线、道具搭配值得借鉴。他们希望“我的商品也出一张这种感觉的图”，而不是自己用文字描述构图——运营说不清“45 度俯拍、左上留白、暖色晨光”这种术语。

用户故事：*“我上传我的商品图和几张参考图（比如竞品的主图、场景图、细节图各一张），平台帮我一张参考出一张图——每张都贴合对应参考的感觉，但商品是我自己的。”* 后续规划：拿竞品的一整套图当参考，直接生成自己的整套图。

## 2. 已确认的决策

以下决策 2026-10-28 与用户确认（A11，见架构文档）：

| # | 决策 |
|---|---|
| 1 | **两条路径都开放**：路径一“借鉴构图”（提示词参考）与路径二“画面参考”（图生图）都提供给用户；路径二需要管理员在执行服务器上**另外安装图生图模型**（依赖 N10 方案），未安装时该选项置灰并说明原因，不影响路径一。 |
| 2 | **只还原感觉，不做一比一复刻**：国内平台普遍允许商品图相互借鉴，海外平台对图片相似度审核更严格。产品设计目标是“还原构图、光线和氛围”，界面文案、提示词组合和（路径二的）重绘幅度都朝这个目标设计；不做“复刻 / 同款 / 一比一”类功能。 |
| 3 | **多张参考图一对一各自生成，不合并**（用户 2026-10-28 澄清）：每张参考图对应一次独立生成任务，产出一张贴合**该参考**的效果图；没有主辅之分、不做多张合并描述。参考图是套图的另一种展开轴（“每张参考一张”与“每种图片类型一张”平行），与 F25 分镜互斥。上限 8 张（与分镜一致），总张数仍受 20 张上限约束。 |
| 4 | **参考图临时使用，不落盘**（代理补充）：参考图只存在于本次请求和内存中的批次里，任务结束即弃；不进商品库、不进 F04 项目归档、不进诊断包和备份（见第 7 节）。 |
| 5 | **模板范围**（代理补充）：路径一是提示词文字，对所有模板可用；路径二需要模板声明 `reference` 图片槽位，初版只给场景类模板（`scene_main` / `detail` / `model` 槽位类型）声明，白底主图不需要。 |
| 6 | **参考模式是独立模式，其余选项不生效**（用户 2026-10-28 补充）：上传参考图后进入参考模式，第 2 步的图片类型、视觉风格、需要模特、品牌资料包、一句话描述、候选张数和卖点分镜全部停用；界面只展示逐张参考的提示词（由视觉模型生成、可修改），“按参考出图”每张参考固定出 1 张，生成固定使用保真场景模板（P1）或画面参考工作流（P2）。 |

## 3. 两条路径

### 3.1 路径一：借鉴构图（提示词参考）

每张参考图交给视觉模型（MagicPrompt 的 vision 能力，决策 A5 默认开启，管理员可关闭），产出**该参考自己的**英文构图描述（镜头、光线、场景、色调），作为该参考的提示词展示给用户（可修改，以改稿为准），走现有文生图 + 商品保真出图；参考模式下不再追加产品类型、视觉风格、模特、品牌等其他片段。

- 每张参考一个任务、一段描述，**互不合并、互不干扰**——不存在“多张打架”的问题。
- 不需要新的生成模型，现有文生图链路直接可用。
- 效果：能借到构图和氛围的大方向，细节还原有限——这与“只还原感觉”的定位一致。
- 看图描述被关闭或没有可用的视觉模型时：参考模式不可用，界面说明缺什么及处理步骤（F68）；普通出图不受影响。

### 3.2 路径二：画面参考（图生图）

参考图作为图生图 / 图像编辑工作流的输入，“把我的商品放进类似这个感觉的画面里”。

- **每个任务的参考就是它自己的输入**：一对一模型下图生图的“单输入”天然成立，无需多图混合（IPAdapter 多图风格混合留待以后评估）。
- **依赖 N10（图生图方案）**：N01 选定的默认模型目前只用于文生图；执行服务器需另外安装图生图模型（如 Qwen-Image-Edit 类指令编辑模型），模板 `requirements` 照常声明，F08 模型清单和依赖检查负责展示缺什么，缺模型时相关模板对用户隐藏（现有机制）。
- 工作流来源：N02 专家制作，或 F57 标准工作流生成器扩展图生图分支（均在 N10 之后）。
- **还原感觉而非复刻**：工作流的去噪幅度 / 参考权重由模板固化在合理区间（偏低），模板审核时把关；界面对路径二的描述统一为“画面参考（还原感觉）”。
- 模板声明 `reference` 槽位（类似品牌资料包 F12 的 `reference_image`）：`"reference": { "image": "参数ID" }`，指向工作流快照里的图片参数；与 `brand_kit.reference_image` 不能指向同一个参数（模板校验报错）。客户端只提交图片数据，服务端按任务填参，白名单边界不变。

## 4. 界面与交互（参考模式）

1. **参考图（可选）入口**：第 2 步新增上传入口，**最多 8 张**，缩略图排布可换行；第 9 张不接收并提示上限。上传时客户端压缩（与画廊选图 F52 相同的 5 MB 上限），服务端按普通图片校验。每张可删除。
2. **上传即进入参考模式**：第 2 步的图片类型、视觉风格、需要模特、品牌资料包、一句话描述、候选张数和卖点分镜**停用并标注“参考模式下不生效”**；平台仍可选（影响后续导出与海外提示）。
3. **逐张提示词**：每张参考上传后由视觉模型在后台生成英文构图描述（列表项显示“描述中…”），多张参考逐张排队描述（本机视觉模型一次只能看一张图，同时发出会排队超时），等待中的显示“排队等待描述…”；描述是 60–120 词的英文段落，覆盖景别与机位、商品在画面中的位置、台面与背景、道具、光线、色调氛围和摄影风格，不提商品种类和品牌；自动填入该参考的提示词输入框：**英文可编辑**（服务端清理后使用，以用户改稿为准）、中文译文只读展示；描述失败可单张重试。vision 未开启时参考模式不可用，提示“借鉴构图需要管理员开启看图描述”。
4. **按参考出图**：按钮替代原两个出图按钮，按 商品 × 参考 展开，**每张参考固定出 1 张**（候选张数不生效）；预计张数实时提示，商品数 × 参考数超过 20 时禁用并说明（F55）。
5. **分镜互斥**：卖点分镜（F25）与参考图互斥，同时使用时提示二选一（分镜入口在参考模式下已停用）。
6. **任务卡片**：按参考展开的任务在卡片上显示**对应参考图的缩略图**，并可展开查看该任务实际使用的提示词（沿用 F56 的 `prompt_used`）。
7. **版权提示**：上传入口下方固定提示——参考图只用于借鉴构图与光线，请使用有权使用的图片（自己拍摄、已授权或无版权限制）；生成结果请勿与参考图雷同。
8. **海外平台加强提示**：所选平台的 `region` 为 `global` 时追加提示——海外平台对图片相似度审核更严格，建议只借鉴构图，上架前自行确认不与参考图雷同。

## 6. 版权与合规边界

- **不做**：竞品图自动抓取、竞品图库或推荐、任何“一键复刻 / 同款”功能——这是红线。
- 界面固定版权提示 + 海外平台加强提示（第 4 节）。
- 生成结果与参考图的相似度检查（过高时警告）挂在 F21 候选图自动筛选下，本期不做。
- 平台导出（F58）不感知参考图；AI 元数据按现有 F22 规则写入。

## 7. 存储与隐私

- 参考图**只在请求与内存批次中存在**：与商品图同样随批次在内存中保留（批次 6 小时过期），**不写入 `Data/`**，不进商品库（F36）、项目归档（F04）、候选清理登记（F39）、诊断包（F44）和备份（F45）。
- 只对提交者本人可见；队列、进度等共享接口不返回参考图。
- 实现时在 AGENTS.md 补充对应规则（参照 F04 项目归档的做法）。

### 8.1 看图模型运行设备（F71）

客户电脑可能是 NVIDIA、AMD、Intel 显卡或 Mac，也可能没有独立显卡。部分显卡跑看图模型会卡住：例如 Windows 上 RX 5600 XT 这类较老的 AMD 卡不在 ROCm 支持列表里，Ollama 改走 Vulkan，看图请求长时间零输出，之后 Ollama 显示模型“已加载”却不占显存，连纯文字请求也卡住，只有卸载模型才恢复；同一台电脑改用 CPU，单张约 8–18 秒就能完成。看图描述因此要按机器自动选择运行设备，而不是假定显卡一定可用。

| 期 | 内容 | 任务 |
|---|---|---|
| P1 | ① 对 Ollama 关闭思考模式（对 Qwen3 混合版有效；实测 Qwen3-VL 不带后缀的标签是思考版，`think:false` 无效，推荐与一键安装改用 `-instruct` 标签，已装思考版时设置里提示改换），看图请求把上下文限制在 4096；② 看图超时后让 Ollama 卸载该模型，清掉卡死状态，放弃等待时同时取消底层请求；③ “自动”模式下，每个“Ollama 地址 + 视觉模型”第一次看图先在 GPU 上最多等 60 秒，没有结果就卸载模型、改用 CPU 重试，并在服务运行期间记住（重启后重新判断），GPU 正常答完的机器不受影响；④ 管理员可在提示词优化设置里把运行设备设为“自动 / 只用 GPU / 只用 CPU”，自动改用 CPU 后设置里提示原因并建议改选“只用 CPU” | T75 |
| P2 | 实测自检：首次配置、更换模型或 Ollama 版本、显卡变化时，用内置测试图分别在 GPU、CPU 上限时实测，选能出结果且更快的设备，按测得速度设定超时；结果按“Ollama 版本 + 模型 + 显卡名称 + 驱动版本”保存在数据目录（只存设备选择和秒数），设置里显示“看图：GPU / CPU，单张约 X 秒”并可重新检测；运行中自动改用 CPU 的结果也写入，重启后不必再卡一次 | T76 |
| P3 | 按硬件给出初始设备和推荐模型（只在 Ollama 与本服务在同一台电脑时读取硬件）：NVIDIA 按显存推荐 8B / 4B；AMD 在 ROCm 支持列表内按显存，较老型号和 Intel 显卡先用 CPU；Apple Silicon 按内存；无独立显卡用 CPU 和 2B。与 ComfyUI 共用同一块显卡且显存较小时，默认让看图走 CPU 或描述完立即卸载，避免挤占出图显存 | T77 |

所有期都只改变看图请求的运行设备和等待方式，不改变“参考图只在内存中短暂存在”的规则；保存的检测结果只有设备选择和耗时，不含图片或提示词；接口只返回设备选择与状态，不返回 Ollama 地址。

## 9. 验收标准（T61）

- 上传 3 张参考图 + 1 个商品：出 3 张图，各自贴合**对应**参考的构图（不是混合感觉）；上传第 9 张被拒并有提示。
- 上传后图片类型、视觉风格、需要模特、品牌资料包、一句话描述、候选张数、卖点分镜均停用并标注；出图按钮变为“按参考出图”。
- 每张参考的提示词可编辑：修改英文后提交，任务卡片 `prompt_used` 显示修改后的提示词。
- 2 个商品 × 8 张参考 = 16 张可提交；再增加商品或参考导致超过 20 张时按钮禁用并说明；每张参考只出 1 张。
- 分镜与参考图同时使用时提示二选一；vision 未开启时参考模式不可用并提示原因，普通出图不受影响。
- 任务卡片显示对应参考缩略图和实际提示词；参考图不出现在商品库、画廊、归档、诊断包中，重启服务后不留任何参考图数据。
- 选海外平台时出现加强提示；国内平台只显示基础版权提示。
- 中英文界面完整；`studio-i18n` 与 `simple-mode` 测试通过。
