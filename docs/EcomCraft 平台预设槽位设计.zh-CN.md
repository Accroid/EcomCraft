## 1. 背景与问题

现状（F05 / F22 已实现）：`Templates/platforms.json` 中每个平台只有一套导出规格——宽、高、补边色、格式（jpg / png）、JPEG 质量、是否要求纯白背景、`verified` 标志和来源说明。管理员可用 `Data/EcomCraft/platforms.json` 覆盖内置预设。

问题：一个电商平台对商品图的要求不是“一个尺寸”，而是**一组图片槽位**，各槽位规则不同：

- 淘宝 / 天猫：1:1 主图（800×800 起才有放大镜）＋ 3:4 无线主图 ＋ 第 5 张白底图（纯白、约 300KB）＋ 1:1 / 3:4 主图视频
- 京东：第 1 张必须纯白白底（无阴影倒影）、单张约 1MB 上限、主图视频 1:1 / 16:9
- 抖音电商：1:1 主图（≥600×600）、严禁水印和促销文字、视频 9:16 / 3:4
- 亚马逊：主图强制纯白、主体占比 ≥85%、单张 ≤10MB

单一规格无法表达这些差异：套图无法按平台出“对”的组合，导出无法按平台上限控制文件大小，禁用内容和 AI 标识规则也无处安放。

## 2. 尺寸之外的平台差异维度

| # | 维度 | 差异示例 | 影响端 |
|---|---|---|---|
| 1 | 槽位结构 | 一个平台 = 白底主图＋场景主图＋3:4 无线图＋视频封面等多个槽位 | 生成（套图组合） |
| 2 | 白底图位置与张数 | 京东第 1 张、淘宝第 5 张、亚马逊仅主图、抖音无强制白底 | 生成（纯抠图分支出几张、排哪） |
| 3 | 主体占比下限 | 约 60%（抖音）→ 2/3（京东）→ 80%（淘宝白底）→ 85%（亚马逊） | 生成（构图与商品位置默认值）、导出（提示） |
| 4 | 阴影 / 倒影 / 道具 | 京东白底不允许阴影倒影；亚马逊主图不允许道具和文字 | 生成 |
| 5 | 单张大小上限 | 京东约 1MB、淘宝约 3MB、抖音约 5MB、亚马逊 10MB | 导出（按上限自动压缩） |
| 6 | 禁用内容（牛皮癣） | 水印、促销文字、价格、二维码、边框、拼图；京东 / 抖音执法最严 | 导出（卖点图只能进允许槽位） |
| 7 | AI 内容标识 | 国内《人工智能生成合成内容标识办法》要求显式标识与平台声明；欧盟、亚马逊对 AI 人物有披露要求 | 导出（F49 可见标识为后续） |
| 8 | 格式 | JPG / PNG 之外，抖音接受 WebP | 导出 |
| 9 | 主图张数上限 | 淘宝 5、京东 5–6、抖音 3–5、亚马逊 1＋8 | 生成（候选张数默认） |
| 10 | 品类特殊规则 | 服饰 AI 模特图披露、食品成分实拍、3C 认证标 | 生成 / 导出（N09 定品类后细化） |

上表数值均为常见公开规范，**必须经 N06 核对官方最新规则后才能置 `verified`**。

## 3. 设计：预设 schema v3（槽位化）

### 3.1 数据结构

`platforms.json` 从“每平台一个 `export` 对象”升级为“每平台一组 `slots`"。示例（淘宝，数值待 N06 核对）：

```json
{
  "id": "taobao",
  "name": { "zh-CN": "淘宝 / 天猫", "en": "Taobao / Tmall" },
  "region": "cn",
  "slots": [
    {
      "id": "white_main",
      "kind": "white_main",
      "name": { "zh-CN": "白底主图", "en": "White main image" },
      "width": 800, "height": 800, "background": "#FFFFFF",
      "format": "jpg", "quality": 92, "max_bytes": 307200,
      "subject_ratio_min": 0.8, "position": 5
    },
    {
      "id": "scene_main",
      "kind": "scene_main",
      "width": 800, "height": 800, "background": "#FFFFFF",
      "format": "jpg", "quality": 92, "max_bytes": 3145728
    },
    {
      "id": "wireless_3_4",
      "kind": "scene_main",
      "width": 800, "height": 1200,
      "format": "jpg", "quality": 92, "max_bytes": 3145728,
      "optional": true
    }
  ],
  "main_image_count": 5,
  "video": { "ratios": ["1:1", "3:4"], "max_seconds": 60, "note": "视频属 F48，本期只记录规格" },
  "forbidden": ["watermark", "promo_text", "price", "qr_code", "border", "collage"],
  "ai_label": { "implicit_metadata": true, "platform_declaration": true, "visible_label": "F49（未开发）" },
  "verified": false,
  "source": "待 N06 核对"
}
```

字段说明：

| 字段 | 位置 | 说明 |
|---|---|---|
| `slots[].kind` | 槽位 | 枚举：`white_main`（白底主图，走纯抠图分支）、`scene_main`（场景主图）、`detail`（细节图）、`model`（模特或手持图）、`video_cover`（视频封面，本期只记录） |
| `slots[].position` | 槽位 | 白底图建议放在第几张（京东 1、淘宝 5），前端以提示展示，不强制排序 |
| `slots[].width` / `height` | 槽位 | 导出画布尺寸；沿用现有校验范围 |
| `slots[].subject_ratio_min` | 槽位 | 主体占比下限（0–1）；低于下限时提示，不阻断 |
| `slots[].max_bytes` | 槽位 | 单张大小上限；导出时按质量二分自动压缩，仍超限时提示 |
| `slots[].optional` | 槽位 | 可选槽位（如 3:4 无线图），套图默认不出、用户勾选后追加 |
| `main_image_count` | 平台 | 主图张数上限，用于套图候选张数的默认与上限提示 |
| `forbidden` | 平台 | 禁用内容枚举；导出含文字的图（如卖点图 F47）时校验目标槽位是否允许 |
| `ai_label` | 平台 | AI 标识策略：`implicit_metadata`（现有 IPTC 元数据）、`platform_declaration`（需在平台后台声明）、`visible_label`（F49 可见标识） |
| `verified` / `source` | 平台 | 语义与 v2 相同：N06 核对官方规则后置真 |

### 3.2 槽位与模板的映射

`slots[].kind` 对应内置模板：`white_main` → 白底主图（纯抠图分支，不调用生成模型）、`scene_main` → 场景图、`detail` → 细节图、`model` → 模特或手持图。**一键套图 = 所选平台的槽位列表展开为模板组合**，例如：

- 淘宝 = 白底主图（第 5 张提示）＋ 场景图 ＋ 细节图 ＋（勾选后）3:4 无线场景
- 京东 = 白底主图（第 1 张提示）＋ 场景图 ＋ 细节图
- 亚马逊 = 白底主图 ＋ 场景附图（非纯白槽位）
- 抖音 = 场景主图 ＋ 细节图（无强制白底槽位）

现有 F55 的“总张数 ≤ 20”上限不变；`main_image_count` 只影响默认张数建议和超限提示。

### 3.3 导出行为

- 每张作品按目标槽位的宽高、格式、质量导出，`max_bytes` 超限时按质量二分重新编码，两次仍超限则导出并在结果中说明。
- `subject_ratio_min` 由商品抠图占画布的比例估算，低于下限时界面提示“商品占比偏小”，不阻断导出。
- `forbidden`：把含文字的图（卖点图 F47）导出到 `promo_text` 禁用的槽位时提示；白底槽位拒绝非纯白图（沿用现有 `require_white_background` 检查，字段并入槽位）。
- AI 标识沿用 F22 的 IPTC 元数据；`platform_declaration` 为 `true` 的平台在导出结果中提示“需在平台后台上传时声明 AI 生成”；可见标识是 F49，本文不实现。

### 3.4 兼容与迁移

- 读取兼容：`export` 单规格的 v2 文件（含 `Data/EcomCraft/platforms.json` 覆盖文件）继续可读，视为一个 `scene_main` 槽位，`require_white_background` 转为 `white_main` 槽位标记。
- 内置 `platforms.json` 升级为 v3 后 `version` 字段改为 3；检测到 v3 时不再接受 v2 专有字段（如有冲突以槽位为准并记日志）。
- 不做存量数据迁移：平台预设无历史数据，重新发布即生效。

## 6. 已确认的设计决策

以下 4 个问题原为待确认项，2026-10-28 已定（用户委托代理决策）：

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | `subject_ratio_min` 是否在生成阶段参与构图 | **仅导出提示**，初版不做生成端联动 | 生成端联动会改变商品位置默认值，影响所有模板且难以独立验证；先在导出端提示，若实际出图经常低于占比要求，再评估生成端联动 |
| 2 | `max_bytes` 两次压缩后仍超限的行为 | **继续导出并在结果中说明** | 拒绝导出让运营白跑；平台上传时也会自行压缩或报错，结果中的说明让运营知情后自行处理 |
| 3 | `video_cover` 槽位本期是否参与套图 | **只记录规格，不参与套图** | 主图视频是 F48（未开发）；预设先记录 9:16 / 3:4 等规格，F48 落地时数据已就绪 |
| 4 | 品类特殊规则（第 2 节 #10）放平台预设还是模板 categories | **等 N09 定主攻品类后再定**，初版不实现品类规则字段 | 规则跟平台走还是跟品类走取决于实际规则形态；F19 品类预设与 F58 平台预设届时都已存在，按规则本质归位，避免现在预设错方向返工 |
