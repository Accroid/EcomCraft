## 1. 产品定位

EcomCraft 让电商运营、设计师和小店老板，**只需要一张商品图和一张想要的参考图**，就能在自己有显卡的 Windows 或 Mac 电脑（或局域网）上，得到可以直接上架的商品图和整套图；不用学模型和工作流，商品不走样，图片不出公司。

- **用户**：
  - 运营人员和小店老板：用简易模式三步出图（传商品 → 选平台和参考图 → 挑图导出），不接触提示词、模型或参数。
  - 平面设计人员：在专业模式（精修台）里调整模型、采样器、LoRA、步数等参数，或做局部修改和指令修图。
  - 管理员（店里的技术人员，或我们提供的部署服务）：负责安装和配置。
- **配置门槛（A15，必须有显卡）**：
  - Windows：NVIDIA 显卡最低 8GB 显存（推荐 16GB 以上）；AMD 仅限 ROCm 支持列表内。
  - Mac：仅 Apple 芯片，最低 24GB 统一内存（推荐 32GB 以上）；Intel 芯片 Mac 不支持。
  - 没有达到门槛的配置明确告知不支持，不做无显卡方案（D5，数值实测后调整）。
- **目标平台（A16）**：重点支持 Windows 和 Mac；Linux 启动脚本保留但暂不投入和验证。
- **销售方式**：开源核心 + 团队版（闭源扩展），按账号数收费（A12、A18）。
- **部署**：一台或多台装有显卡的电脑运行 ComfyUI，其中一台同时运行 EcomCraft 平台；团队成员在局域网内用浏览器访问同一个页面，平台自动把任务分派到空闲的显卡电脑。
- **市场**：同时支持国内平台（淘宝/天猫、京东、拼多多、抖音等）和海外平台（亚马逊、Shopify、TikTok Shop 等）；界面和文档提供中文和英文。
- **差异化**：完全本地生成（商品图不出公司）、商品保真、照参考图做出可上架的图和整套图、按平台规范一键导出。

## 2. 已确认的决策

| 编号 | 决策 |
|---|---|
| A1 | 部署形态为“一台显卡电脑 + 浏览器访问”，并支持局域网多台显卡电脑；用户只看到一个前端页面，任务自动分派。 |
| A2 | 目标用户是运营人员、平面设计人员和小店老板：默认界面是只保留必要步骤的简易模式；任何账号都可以切换到专业模式，不按角色限制（管理员仍单独负责安装、配置和审核）。 |
| A3 | 国内外平台都要支持；界面、文档和平台预设同时提供中文和英文。 |
| A4 | 用户不写提示词：用一句话描述（中英文均可）加风格选项，由已接入的在线大模型（MagicPrompt）优化成提示词。（2026-10-31 注：A14 单入口实施后，简易模式不再展示一句话描述和风格选项，这些控件代码保留；能力仍在专业模式可用。） |
| A5 | 看图描述（把参考图发给视觉模型读出构图）默认开启，默认视觉模型是本机 Ollama，图片不出本机；管理员可以关闭，或改用云端视觉服务（图片会离开本机，须管理员确认）。把商品图发给视觉模型自动描述商品仍默认关闭，由管理员开启。（2026-10-29 修订：原为看图描述默认关闭） |
| A6 | 不做云端生成（2026-10-31 修订，原为“保留云端生成能力、MVP 不开发”）：生成只在本机自启动或局域网登记的执行服务器上，不向任何云端生成服务发送请求；看图和提示词模型的云端选项不受影响（A5）。调度层仍按“执行方”抽象实现，但只产生本机和局域网执行方。 |
| A7 | 作品存储默认在平台服务器本机，管理员可改为 NAS 或其他电脑的共享文件夹；系统数据固定在本机。见需求文档 D12、R11。 |
| A8 | 作品在平台内仅本人可见，存储层不做隔离。见需求文档 D9。 |
| A9 | 暂不自己接单验证需求；改为发布后找 3–5 个种子团队试用。 |
| A10 | 单服务器先行：MVP 按“一台平台服务器（同时是执行服务器）”部署和验收。多服务器接入、调度与存储的架构和代码支持保留；多机实测（F28 / T33、N08）暂缓，等客户提出需求或测试环境就绪再做。 |
| A11 | 参考图路线升级为“照参考图做”（F74，2026-10-31 修订）：目标是参考图 + 商品图直接输入编辑模型融合（路线 E），生成后定位商品、贴回原商品细节并校验走样，不再依赖“看图写提示词 + 局部重绘”的旧路线；具体路线和模型待 G1 实测验定。允许与参考图“高度相似”（D2），边界见 A17；不做竞品链接抓取、图库或推荐。参考图临时使用不落盘。旧的双路径（借鉴构图 / 画面参考）中，画面参考（T62）被 T84 取代，借鉴构图保留为 `reference_mode: composition` 回退。 |
| A12 | 盈利方式（2026-10-31 修订）：开源核心 + 团队版（A18），按账号数收费。账号仍只分“管理员”和“普通账号”两种，不做复杂的角色与权限设计；团队版功能（局域网多服务器、用量统计、审核流程、行业模板包等）放在独立闭源扩展里，授权仍只限制账号数量，不用水印或功能阉割保护开源版。 |
| A13 | 界面与操作改版 v4（F60–F67）：管理功能收进管理员的“管理”菜单，原生引擎只给管理员；手机只做简易模式；设计师可上传 ComfyUI 工作流，上传者自己马上能用，其他账号要经审核发布；看图描述默认开启并在缺少视觉模型时引导配置；候选图可收藏，个性化分析暂缓。详见《EcomCraft 界面与操作改版需求》。（2026-10-31 修订：原“简易模式先选任务（照参考图做 / 做一张图 / 出一整套）”被 A14 单入口取代。） |
| A14 | 出图页单入口（F61 修订，P4）：只保留“照参考图做”，去掉“做一张图”“出一整套”入口；整套图也由参考图驱动（多张参考按图位出套图）。页面三步：传商品 → 选平台和尺寸 + 参考图（可改图位、相似程度、勾选白底图）→ 挑图导出。旧入口相关的控件从简易模式隐藏（代码保留，等 G2 通过后决定是否清理），衔接功能迁移见 T90。 |
| A15 | 硬件门槛（P1、D5）：必须有显卡才能用，不做无显卡或云端出图方案；配置不够时明确告知不支持。最低配置：Windows NVIDIA 8GB 显存、Mac Apple 芯片 24GB 统一内存；Intel Mac 不支持，AMD 仅限 ROCm 支持列表内。数值实测后调整。 |
| A16 | 平台重点（P2）：重点支持 Windows 和 Mac；Linux 启动脚本保留，但暂不投入开发和验证。 |
| A17 | 相似度边界（D2，见《实施计划》1.3）：允许用户自己上传参考图并生成与参考图高度相似的构图、场景、光线；文字、Logo、水印不进入成品（文字由系统重新排版）；含真人模特的参考图不沿用其面孔（首批直接提示不支持）；保留版权提示和海外平台加强提示；不做竞品链接抓取、竞品图库或推荐，对外不用“复刻竞品”宣传，界面统一用“照参考图做”。 |
| A18 | 版本（P6）：开源核心 + 团队版（闭源扩展程序集），按账号数收费；拆分方式见 T109。 |

## 5. 一键套图的数据流

```
1. 运营从商品库选择商品（或上传新图）→ 确认抠图结果，可拖动或缩放商品位置
2. 选平台（如亚马逊）和风格（带示例图），可选写一句描述，如“放在木桌上，早晨阳光”
3. 提示词服务：描述 + 风格 → MagicPrompt → 英文提示词（只作为提示词文本）
4. 生成编排：亚马逊套图 = 白底主图（纯抠图分支，不调用生成模型）+ 场景 + 细节 + 模特，每种 4 张候选
5. 每个任务按快照白名单逐项校验 → 检查此人的排队上限
6. 调度：分派到排队最少、且有所需节点和模型的执行服务器（多台并行）
7. ComfyUI 输出生成图 → 回传平台服务器（输入画布由平台按抠图和商品位置在本地生成）
8. 后处理：用本地抠图作为蒙版，按同一位置把原商品像素贴回（标准工作流：细节取原图，光影取生成结果，并加接触阴影） → 先存本机，再同步到作品库 → 画廊
9. 运营挑图 → 导出：平台尺寸、纯白检查、AI 元数据 → 下载 zip 或导出到共享文件夹
```

将来接入云端时，只替换第 6–7 步的执行方，抠图、保真合成和导出仍在本地完成。（2026-10-31 修订：按决策 A6 不再做云端生成，本句仅作为历史设计描述保留；生成永远在本机或局域网执行服务器上完成。）

## 6. 关键设计约定

### 6.1 安全边界（沿用 AGENTS.md）

- 客户端只提交模板 ID、工作流 ID、服务端发布的参数白名单、商品库 ID 等标识，不得提交任意 ComfyUI JSON、节点图、后端选择器或文件路径。
- 大模型的输出只能填入提示词文本字段，不能决定工作流、节点、参数或执行服务器；以后的分镜功能也必须让每一项再经过模板和白名单校验。
- 生成任务只发往已登记的执行服务器；在线大模型只处理文字；不向任何云端生成服务发送请求。
- 普通用户接口不返回服务器地址、存储路径、原始工作流、其他用户的任务或密钥。

### 6.2 国际化

- 界面：工作台所有文字放入 `zh-CN` / `en` 翻译表，切换语言不刷新页面；测试检查英文模式下没有残留中文。已实现：中文原文即翻译 key，英文表为 `Studio/lang/en.js`，测试为 `Tests/studio-i18n.test.cjs`。服务端返回的错误在英文模式下按错误码显示通用英文说明，服务端消息本身的本地化尚未实现。
- 内容：模板、风格、平台预设的名称和说明在数据中同时保存中英文字段。
- 提示词：用户可以用任一语言描述，提示词服务统一输出英文提示词。
- 文档：EcomCraft 文档中英文同步编写。

### 6.3 平台预设

一份可编辑的配置文件，列出国内外平台。每个平台记录：中英文名称、图片尺寸、补边颜色、合规规则（如亚马逊主图不使用生成模型、必须纯白背景）、是否写入 AI 元数据。具体数值在开发时逐项核对官方规范，并由管理员确认。

目前每个平台已按“槽位”组织（F58，已实现待验收）：每个平台由多个图片槽位组成（白底主图、场景主图、3:4 无线图、视频封面等），各有尺寸比例、主体占比、单张大小上限、禁用内容和 AI 标识规则，套图按槽位组合模板，设计见 [EcomCraft 平台预设槽位设计](EcomCraft%20平台预设槽位设计.zh-CN.md)；规范数值待 N06 核对。

## 9. 明确不做

- 面向小卖家的公开 SaaS、积分和在线支付系统。
- 水印预览等 SaaS 式限制。
- 复杂的角色与权限体系、按功能分级收费（A12）。
- 为每个客户单独搭工作流（差异放进品类预设和品牌资料包，超出部分作为付费定制）。
- 无显卡方案和云端出图（2026-10-31，A6、A15：必须有显卡才能用，配置不够时明确告知不支持；不做无显卡或云端生成方案。看图和提示词模型的云端选项不受影响）。
- 自己接单验证需求。

## 10. 开发顺序

2026-10-31 起按《[EcomCraft 实施计划](EcomCraft%20实施计划.zh-CN.md)》的阶段执行，并与《[EcomCraft 重构计划](EcomCraft%20重构计划.zh-CN.md)》（R00–R24）穿插（顺序见其第 7 节）：

1. **阶段 0 规划落文（T81）**：目标写进仓库文档和总表。
2. **阶段 1 路线实测（N11、N09/N03、T82、N12）→ G1 决策关卡**：选定参考图路线、模型和量化版本；G1 不通过不得进入阶段 2。T82、N12 可与重构阶段 A–B 并行，都不改平台代码。
3. **阶段 2 参考图 v2（T83–T90）→ G2 效果验收**：参考图分析、融合工作流、出图流程接入、商品定位贴回校验、比例适配、异常处理、单入口。
4. **阶段 3 开箱即用（T91–T96）**：硬件检测分档、模型配方与一键下载、向导样例自检、Mac 适配、安装包。
5. **阶段 4 套图和详情（T97–T102）**：平台图位数据、按图位出整套、卖点信息、版式、风格一致、内置参考图库。
6. **阶段 5 专业模式（T103–T108）**：精修台。
7. **阶段 6 发布（T109–T110）**：开源/团队版拆分、发布文档。

阶段 3、4、5 在 G2 之后互不阻塞可并行，但同一文件的任务不要同时改。每个任务的详情、验收和提示词见开发总表“开发任务”工作表。
