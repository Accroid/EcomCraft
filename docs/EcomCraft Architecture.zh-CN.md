## 1. 产品定位

EcomCraft 是**面向电商运营人员和小店老板的局域网商品图生产平台**：

- **用户**：不熟悉设计的运营人员和小店老板。他们只需要上传商品图、选平台和风格、挑图下载，不接触提示词、模型或参数。管理员（店里的技术人员，或我们提供的部署服务）负责安装和配置。
- **部署**：一台或多台装有显卡的电脑运行 ComfyUI，其中一台同时运行 EcomCraft 平台；团队成员在局域网内用浏览器访问同一个页面，平台自动把任务分派到空闲的显卡电脑。
- **市场**：同时支持国内平台（淘宝/天猫、京东、拼多多、抖音等）和海外平台（亚马逊、Shopify、TikTok Shop 等）；界面和文档提供中文和英文。
- **差异化**：完全本地生成（商品图不出公司）、商品保真、团队协作、按平台规范一键导出。

## 2. 已确认的决策

| 编号 | 决策 |
|---|---|
| A1 | 部署形态为“一台显卡电脑 + 浏览器访问”，并支持局域网多台显卡电脑；用户只看到一个前端页面，任务自动分派。 |
| A2 | 目标用户是不熟悉设计的运营人员和小店老板：默认界面只保留必要步骤，专业参数只对管理员可见。 |
| A3 | 国内外平台都要支持；界面、文档和平台预设同时提供中文和英文。 |
| A4 | 用户不写提示词：用一句话描述（中英文均可）加风格选项，由已接入的在线大模型（MagicPrompt）优化成提示词。 |
| A5 | 在线大模型只处理文字。把商品图发给在线视觉模型（自动描述商品）默认关闭，由管理员开启，或改用本地视觉模型。 |
| A6 | 保留云端生成能力（执行方抽象、三段式生成流程），**MVP 不开发云端生成功能**，见需求文档 D11、R10。 |
| A7 | 作品存储默认在平台服务器本机，管理员可改为 NAS 或其他电脑的共享文件夹；系统数据固定在本机。见需求文档 D12、R11。 |
| A8 | 作品在平台内仅本人可见，存储层不做隔离。见需求文档 D9。 |
| A9 | 暂不自己接单验证需求；改为 MVP 发布后找 3–5 个种子团队试用。 |

## 5. 一键套图的数据流

```
1. 运营从商品库选择商品（或上传新图）→ 确认抠图结果，可拖动或缩放商品位置
2. 选平台（如亚马逊）和风格（带示例图），可选写一句描述，如“放在木桌上，早晨阳光”
3. 提示词服务：描述 + 风格 → MagicPrompt → 英文提示词（只作为提示词文本）
4. 生成编排：亚马逊套图 = 白底主图（纯抠图分支，不调用生成模型）+ 场景 + 细节 + 模特，每种 4 张候选
5. 每个任务按快照白名单逐项校验 → 检查此人的排队上限
6. 调度：分派到排队最少、且有所需节点和模型的执行服务器（多台并行）
7. ComfyUI 输出“生成图 + 商品蒙版” → 回传平台服务器
8. 后处理：用蒙版把原商品像素贴回 → 先存本机，再同步到作品库 → 画廊
9. 运营挑图 → 导出：平台尺寸、纯白检查、AI 元数据 → 下载 zip 或导出到共享文件夹
```

将来接入云端时，只替换第 6–7 步的执行方，抠图、保真合成和导出仍在本地完成。

## 6. 关键设计约定

### 6.1 安全边界（沿用 AGENTS.md）

- 客户端只提交模板 ID、工作流 ID、服务端发布的参数白名单、商品库 ID 等标识，不得提交任意 ComfyUI JSON、节点图、后端选择器或文件路径。
- 大模型的输出只能填入提示词文本字段，不能决定工作流、节点、参数或执行服务器；以后的分镜功能也必须让每一项再经过模板和白名单校验。
- 生成任务只发往已登记的执行服务器；在线大模型只处理文字；不向任何云端生成服务发送请求。
- 普通用户接口不返回服务器地址、存储路径、原始工作流、其他用户的任务或密钥。

### 6.2 国际化

- 界面：工作台所有文字放入 `zh-CN` / `en` 翻译表，切换语言不刷新页面；测试检查英文模式下没有残留中文。
- 内容：模板、风格、平台预设的名称和说明在数据中同时保存中英文字段。
- 提示词：用户可以用任一语言描述，提示词服务统一输出英文提示词。
- 文档：EcomCraft 文档中英文同步编写。

### 6.3 平台预设

一份可编辑的配置文件，列出国内外平台。每个平台记录：中英文名称、图片尺寸、补边颜色、合规规则（如亚马逊主图不使用生成模型、必须纯白背景）、是否写入 AI 元数据。具体数值在开发时逐项核对官方规范，并由管理员确认。

### 6.4 存储

| 数据 | 位置 |
|---|---|
| 系统数据：账号数据库、审核快照、模板与平台预设配置、作品索引、缩略图 | 平台服务器本机 `Data/`，不可更改 |
| 内置模板和默认平台预设 | 扩展目录，随版本发布 |
| 作品：商品原图、生成结果 | 作品库位置：本机（默认）、NAS 或共享文件夹 |
| 导出包 | 浏览器下载，或导出位置（共享文件夹） |

### 6.5 代码组织

遵守“最小改动”原则：不一次性重构现有文件，新功能放在新文件中。

```
src/Extensions/EcomCraft/
├─ EcomCraft.cs                  注册入口（已有）
├─ MagicPrompt/                  在线大模型（已有）
└─ Studio/
   ├─ StudioApi.cs、WorkflowReview*.cs、WorkflowDiscovery.cs 等（已有）
   ├─ Templates/                 模板、套图、平台预设
   ├─ Generation/                编排、调度、执行方、按人限流
   ├─ Prompting/                 提示词服务（封装 MagicPrompt）
   ├─ PostProcess/               商品保真合成
   ├─ Products/                  商品库
   ├─ Export/                    尺寸、打包、元数据、合规检查
   ├─ Storage/                   作品库位置、同步、迁移、清理
   ├─ index.html、studio.js、studio.css（已有）
   ├─ i18n.js、simple.js 等新前端脚本
   └─ languages/zh-CN.json、en.json
```

## 9. 明确不做

- 面向小卖家的公开 SaaS、积分和在线支付系统。
- 水印预览等 SaaS 式限制。
- 为每个客户单独搭工作流（差异放进品类预设和品牌资料包，超出部分作为付费定制）。
- MVP 阶段的云端生成和自己接单验证。

## 10. 开发顺序

1. **平台底座**：F28 实测 → F29 调度 → F30 画廊与改派 → F31 多人部署 → F32 存储；F24 国际化骨架尽早完成，之后每个新功能直接双语开发。
2. **电商出图**：F01 模板 → F37 提示词服务 → F07 简易模式 → F02 保真（依赖 N02）→ F35 抠图确认 → F20 测试台 → F03 套图与批量 → F36 商品库 → F05 导出 → F22 合规 → F08 模型清单。
3. **易用与运维**：F38–F46，最后是 F10 README 与演示。
