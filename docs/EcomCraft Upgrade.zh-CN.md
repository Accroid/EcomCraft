# EcomCraft 升级与数据说明

> **语言：** 简体中文 · [English](EcomCraft%20Upgrade.md)

本文说明升级 EcomCraft / SwarmUI 时哪些数据会保留、如何备份和恢复系统数据。适用于在局域网内部署的管理员。

## 数据放在哪里

| 数据 | 位置 | 升级时 |
|---|---|---|
| 系统数据（账号数据库、审核快照、模板、存储设置、商品库索引、候选图登记） | 平台服务器 `Data/` 目录（含 `Data/EcomCraft/`） | 保留，不要删除 |
| 生成的作品 | 平台服务器输出目录；设置作品库位置后另复制到 NAS 或共享文件夹 | 保留 |
| 模型 | `Models/`（或各执行服务器自己的模型目录） | 保留 |
| 程序代码 | `src/` 等仓库目录 | 由升级替换 |

`Data/`、`Output/`、`Models/` 都不属于代码：升级（拉取新代码后重新构建）不会改动它们。不要手工编辑或删除这些目录里的文件。

## 升级步骤

1. 备份系统数据（见下节），确认备份 zip 已下载保存。
2. 停止正在运行的服务（关闭启动它的窗口或停止 Windows 服务）。
3. 拉取新代码并切换到 `dev` 分支（`git fetch && git checkout dev && git pull`）。
4. 用原来的启动脚本启动（如 `launch-windows.bat`）。Release 模式下扩展程序集按 Git 提交缓存，提交变化后会自动重建；构建需要几分钟。
5. 启动后打开工作台，检查版本号和常用功能是否正常，再让团队继续使用。

### 升级后需要注意什么

- **工作流重新审核**：内容指纹基于转换后的执行图计算。升级若改变了工作流转换逻辑，已发布的工作流可能显示"待重新审核"；重新审核前用户继续使用旧快照，出图不受影响。
- **存储位置不变**：作品库与导出位置设置保存在 `Data/EcomCraft/storage.json`，升级后原样生效。
- **未选候选图清理**：清理登记保存在 `Data/EcomCraft/candidates.json`，升级不影响已选中的作品。

## 备份系统数据

管理员在 **画廊 → 存储设置 → 系统数据备份与恢复** 中点击"备份并下载"：

- 备份 zip 包含 `Data/EcomCraft/` 下的配置、审核快照、模板和商品库索引，以及账号数据库（`Users.ldb` 等）和角色设置（`Roles.fds`）。
- 不包含生成的作品、商品图片文件和模型；作品请通过作品库位置或单独复制保存。
- 也包含项目归档记录 `projects.json`，其中有员工作品实际使用的提示词；备份只有管理员能创建和下载，请妥善保管备份文件。
- 每个文件在清单（`manifest.json`）中记录大小和 SHA-256，恢复时逐个校验。
- 备份只在服务器上临时保留一天，请及时下载保存。

## 恢复系统数据

1. 管理员在 **画廊 → 存储设置** 中点击"选择备份文件恢复"，选择之前下载的备份 zip。
2. 确认提示后，服务端先校验整个备份（任何文件的大小或内容不符都会中止，不会改动现有数据），再写入 `Data/EcomCraft/`。
3. 账号数据库文件在服务运行时被占用，无法直接替换：它们会放入 `Data/EcomCraft/restore-staging/`。需要完整恢复账号时，停止服务，把该目录中的文件复制到 `Data/` 同名位置，再启动服务。
4. 恢复完成后重启服务，使模板、审核快照和存储设置全部生效。

恢复只影响系统数据，不会删除或覆盖任何已生成的作品。
