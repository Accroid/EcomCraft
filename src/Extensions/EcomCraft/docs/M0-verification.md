## 首次宿主加载检查（开发者）

1. 在测试副本构建宿主并用 `--environment dev --host localhost` 启动；检查扩展加载错误及 API 注册错误。
2. 用 Owner/Admin 登录：标签可见、初始请求成功、刷新与下载可用，scope 为 configuration_snapshot_only。
3. 用默认 User、PowerUser 登录：标签隐藏；手工 POST API 也必须拒绝，不得只依赖页面隐藏。
4. 无会话/无效会话调用：宿主拒绝。未授权调用的响应不得含 nodes、checks、后端地址或设置。
5. 在测试副本切换四个关键设置：认证、本机绕过、按用户隔离、自动拉取；刷新后分别出现相应阻断。不要为了测试把生产认证关闭。
6. 配置远程 Swarm：核对继续转发开启/关闭时报告的差异；记录子后端的主控 ID 与远端 ID，重连后确认页面未把旧 ID 当业务身份。
7. 故意使诊断请求失败：旧节点和旧下载报告应清除；恢复后可以再次刷新。
8. 在现代 Chrome/Firefox/Safari、窄屏及浅/深主题中检查键盘焦点、内容换行、页面滚动和下载。

证据：记录测试操作者、日期、宿主/扩展版本、每种账号的预期/实际响应；截图/报告存放内部受控位置，不将会话或密钥复制进 Git。

## 六项 Spike 的实际操作清单

共同前提：独立测试环境；无真实客户素材；至少两台独立生成 PC，主控可与其中一台重合；已固定模型/工作流和节点版本；节点管理端口仅向主控开放。所有状态初始均为 **未执行**。

### SPIKE-01：远程接入与执行身份

- 对应：FR-01、FR-02；AT-01、AT-02。
- 操作：按官方多 GPU 文档登记远程 Swarm，在每台独立生成 PC 上使用同一个已验证的最小工作流重复生成合成测试图；核对主控结果和实际执行机器的日志/监控。
- 通过标准：每台 PC 能实际执行；输出可回传；能够识别实际执行端，而不是仅知道配置的目标。两个 URL/配置指向同一台 PC 不算通过。
- 本切片支持：查看已登记配置及关联执行端，导出当前快照。
- 缺口：没有持久化实际任务/节点映射，不能将快照冒充执行证据。
- 需记录：机器清单、版本、工作流、人工测试编号、实际执行端、结果校验、预期/实际、操作者和时间。

### SPIKE-02：逐任务本地约束

- 对应：FR-04；AT-06、AT-07、AT-08。
- 操作：先检查完整执行拓扑（包括直接 Comfy API 的去向、转发及自定义工作流外联）；验证所有 UI/API 入口、重试、超时和故障路径。停止全部本地节点后，重复提交仅本地任务，记录受控网络观测与服务商调用记录。
- 通过标准：服务端持久化并强制执行授权范围；无授权不得上传任何输入，也不得更换服务商；不能因当前没配云端而声称策略已强制。
- 本切片支持：提示认证与转发配置风险。
- 缺口：未实现逐任务策略与云端适配，当前不能验收此项；应记录为未实现/阻断，而非成功。
- 需记录：每个入口、任务授权、实际去向、失败/重试行为、负向网络证据和无密钥的日志摘要。

### SPIKE-03：健康、维护与能力

- 对应：FR-02；AT-03、AT-04。
- 操作：分别停止节点进程、断开测试网络、停用后端；使用不匹配工作流/模型；观察已排队、运行中及新提交任务。仅在有明确能力登记和维护机制后验证其强制过滤。
- 通过标准：未知/离线/维护/未批准能力不接新任务；运行中超时不直接推断远端已停止；记录成功心跳而非页面刷新时间。
- 本切片支持：区分引擎报告状态、启用/预留与容量信号；未知不报容量。
- 缺口：未实现独立心跳、能力审批和业务维护状态，未接管原生调度。
- 需记录：状态变更时间、最后成功联系时间、实际执行任务、错误摘要和恢复行为。

### SPIKE-04：集中归档

- 对应：FR-03；AT-12、AT-13。
- 操作：生成合成图和允许范围内的较大文件，分别模拟回传断网、归档中断及测试磁盘空间不足；核对文件内容/哈希及任务终态。不得在生产磁盘制造故障。
- 通过标准：必要输出和元数据已可靠归档才完成；失败可追溯；原图不被覆盖；重试不覆盖原记录。
- 本切片支持：明确提醒宿主异步保存的完成边界。
- 缺口：未实现业务任务、归档确认或失败恢复。
- 需记录：输入/输出哈希、文件引用、落盘时间、任务状态时间、失败类别、重试尝试。

### SPIKE-05：私有素材与显式发布

- 对应：FR-01、FR-05；AT-09、AT-10、AT-11。
- 操作：测试员工 A 上传合成素材并生成，B 尝试列表、直接 URL、ID/API、下载和修改；有公共发布功能后再验证发布/下架及来源追踪。管理员与普通员工分开测试。
- 通过标准：A 的未发布输入/结果对 B 不可读；发布后可按规则使用；下架后拒绝；所有检查由服务端实施。
- 本切片支持：报告按用户目录隔离设置，不声称设置即完成权限验收。
- 缺口：未实现 Asset/公共发布；当前不能通过完整验收。
- 需记录：匿名化账号角色、操作、预期/实际、响应状态/摘要、发布人及来源记录；不保存会话令牌。

### SPIKE-06：上游升级与回滚

- 对应：FR-06；AT-14、AT-15。
- 操作：人工明确 origin/upstream 与稳定基线；在独立集成分支和测试副本引入一组上游变更，执行回归；模拟发布失败，恢复上一软件与兼容配置，核对任务及素材未丢失。
- 通过标准：有版本/测试/批准/发布/回滚记录；应用、配置、数据库、工作流与模型分别管理；不能仅 reset 代码就认为完成回滚。
- 本切片支持：报告自动拉取设置风险；独立目录降低核心冲突。
- 缺口：尚未配置 upstream 或改变团队分支策略；没有发布审批和回滚工件。本批没有执行任何 merge/reset/部署。
- 需记录：提交范围、测试集、工件和配置版本、审批人、回滚时间、数据完整性检查。
