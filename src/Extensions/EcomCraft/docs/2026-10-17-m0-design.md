# EcomCraft M0：管理员节点诊断设计

状态：用户已批准“独立扩展 + M0 节点诊断”范围，2026-10-17 开始实现。
需求基线：仓库根目录 `EcomCraft_产品需求与开发说明_V0.1.md` 的正文 V0.2。

## 范围

新增代码、测试及文档只放在 `src/Extensions/EcomCraft/`。不修改核心、启动器、现有数据或 Git 远端；不接管调度、不调用生成、不安装节点、不自动出网、不更改配置。此切片为 FR-01/02/04/05/06 和 SPIKE-01～06 提供接入前诊断，不宣称完成这些需求。

## 架构

- `EcomCraft.cs`：扩展生命周期、管理员权限、脚本样式和 API 注册。
- `Diagnostics/DiagnosticSnapshot.cs`：无宿主依赖的只读观测模型。
- `Diagnostics/ReadinessEvaluator.cs`：纯函数，本机配置检查、引擎容量信号及未验证事项。
- `Diagnostics/SwarmSnapshotReader.cs`：只读取宿主设置及后端的白名单字段；不序列化设置对象、地址、令牌、日志、提示词或文件路径。
- `Diagnostics/DiagnosticsApi.cs`：`POST /API/EcomCraftGetDiagnostics`，需要有效会话和专属权限；输出白名单 JSON。
- `Tabs/Text2Image/EcomCraft.html`、`Assets/ecomcraft.js`、`Assets/ecomcraft.css`：复用现有主题的只读管理员页，手动刷新和下载当前报告。

## 权限

预注册 `view_extension_tab_ecomcraft`，默认 `ADMINS`，同时用于宿主生成的标签和诊断 API，避免宿主自动创建默认 USER 权限。页面在会话权限就绪前保持隐藏且不发请求；服务端另行检查权限，不能靠隐藏页面授权。诊断面向管理员；宿主未启用认证时，明确报告配置阻断，这并不是扩展替宿主建立了认证。

## 观测与判定

- `sampled_at` 仅代表主控读取内存快照的 UTC 时间，不是心跳时间。
- 后端配置 ID 不是 EcomCraft 稳定节点 ID；远程执行子后端 ID 可随重连改变。
- 用 `SwarmSwarmBackend.Parent` 对象关联远程执行子后端，不能假定 `BackendData.AbstractParent` 总已赋值。
- 只有引擎状态 running、启用、非关闭预留、无资源预留、无模型加载预留、可加载模型且容量未满的执行端，才报告 `engine_reports_capacity=true`。这不是可安全调度的结论。
- 远程主控配置也必须处于 running/启用/非预留状态；转发开启、未知类型或无可观察执行端时，不报可用容量。
- 配置中的地址、Header、密钥一律不读取或输出。远程地址的内网属性、独立物理主机身份、已验证能力、模型/工作流版本、成功心跳和最近错误均不能从现有字段可靠得出，保留为空/待验证。
- 后端集合并发变化时按一次快照观察；单个后端读取异常输出 `observation_failed`，不吞掉后报成功，也不回显异常消息。
- 认证关闭、localhost 绕过、输出未按用户隔离、自动拉取更新、启用的远程节点允许继续转发，以及观测失败是阻断项。自动换端口是提醒项。
- 没有后端是阻断；未配置至少两个远程 Swarm 后端为待验证。两个配置不等价于两台 PC。
- 总体状态仅为 `blocked` 或 `pending_verification`，不会有 `ready`。六个 Spike 全部初始为 `pending_verification`，不能由静态检查代替。

## 界面

单一工作区：范围说明、刷新/下载工具条、总体结论、配置检查、节点及执行端列表、六项实测门槛。沿用宿主字体和颜色变量，不引入外部字体、CDN、图片或框架。状态必须有文字说明；键盘可操作、加载/失败提示可读、移动端自然换行。下载仅导出成功读取的当前报告，失败后清空旧报告以免把旧快照当最新数据。

## 验证与限制

纯 C# 控制台测试链接观测模型和判定器，不启动宿主、不访问 GPU/网络/用户数据。Node 内置测试运行真实前端脚本，覆盖权限门、加载防重、错误清理、渲染和导出。源代码契约检查覆盖权限名、资源路径、禁止网络/生成调用和敏感字段白名单。C# 编译、宿主加载、真实账号越权、双机生成、归档失败和回滚必须由有环境的开发者实测，记录在 `docs/M0-verification.md`。
